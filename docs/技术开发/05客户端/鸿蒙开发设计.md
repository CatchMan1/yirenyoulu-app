# 鸿蒙客户端开发设计

保留ArkTS/ArkUI及原项目，独立新仓库逐页迁入经过审查的业务代码；不改原Gitee代码、历史、远程、数据库。原构建基线API21，旧文档API12描述不能直接作为新版约束；正式发布SDK要求在实施时核验。当前新仓库尚无迁入前端工程。

目标目录frontend/harmony，按pages/components/services/models组织即可；不增加无业务需要的抽象层。优先复用现有页面布局和有效组件，替换旧请求、缓存生成ID和敏感日志。

HTTP统一封装超时、取消、DTO解码、200/201/202/204、错误码与request_id。204不解析JSON，业务失败不返回空对象当成功。不用ESObject/any掩盖类型冲突；不照搬旧文档中的强制转换和仅200成功判断。

用户身份保存在平台安全存储能力中；具体接口依据已锁SDK实测，不把普通Preferences等同于安全凭据容器。访问token短期内存，刷新凭据受保护；退出/注销清除用户缓存。页面退出释放请求与定时器，回前台从服务端恢复任务/会话状态。

地图使用统一适配器；高德为已有方向，具体鸿蒙SDK/授权兼容性待核对。位置权限拒绝不阻止手动选城市。未知坐标/地图失败按产品文档降级。

验证：ArkTS编译、关键UI状态、契约fixture、401刷新竞争、行程冲突与AI重试，再模拟器/真机与新后端联调。没有DevEco/设备时明确缺项；静态阅读与后端单测不能替代客户端验收。签名材料保持本地/受控密钥服务，不放入Git。
