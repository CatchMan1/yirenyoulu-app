# Agent、协同推荐与伴游

免费模型提供方与模型未确定。所有模型访问在后端；缺少服务或免费额度耗尽返回不可用，不自动调用付费接口。

## 行程生成

本次显式city/date/budget/preferences/request_text优先于历史。结构化表单与文本有可预检冲突时返回422；任务受理后发现冲突则failed/PLAN_INVALID要求澄清，不静默替换城市/日期。历史行为只提供符合硬约束的候选排序。

当前受控工具仅search_places（同城active且来源允许计算、kind/tags、limit≤50）；地点事实由程序重新读取并保存快照。交通估算提供方未接入，缺失时明确未知。无任意SQL、shell或任意URL工具；模型只得到必要字段。每任务最多8次调用，总截止120秒，单次调用超时与结果大小由适配器限制；重试最多2次且不能延长截止时间。

模型输出仅允许候选place_id、日期、起止分钟、说明与估算。后端重新取事实，不接受模型编造名称、坐标、价格。统一校验：有效同城、日期范围、非住宿项目0≤start<end≤1440、非住宿项目无时段冲突、同日不重复地点、最多14天100项；住宿按每晚一个项目表达，规则见下文，不拆成两段重复收费。交通时间未知不宣称可赶到；已知交通时长需计入相邻间隔检查。

预算按计价单位和次数计算已知成本下界与估算，未知成本单列。已知下界超预算拒绝保存；未知总额可保存但警告预算不完整；估算与事实分别存取展示。程序校验失败返回可解释错误，不伪装生成成功。

## 持久任务与竞争

queued→running→succeeded/failed/timed_out/cancelled；POST返回202并带任务ID。user+Idempotency-Key与请求摘要绑定，同键同输入返回原任务，不同输入409。GET查询数据库；客户端重启通过本人任务列表找回，不能只有内存轮询。

worker领取用行锁、lease_until与递增lease_generation。最终事务锁job并检查generation、running、deadline和用户有效性，再写trip/items、服务端行为和succeeded；任一失败全回滚。trip.generation_job_id唯一；取消/超时回收与提交竞争同一行锁，终态不得被过期worker覆盖。超过截止但未领取的排队任务也应由清理器置timed_out。数据库故障不能报成功。

终态失败若用户明确重新生成使用新幂等键；网络断线重试使用旧键查回任务。允许取消非终态，终态取消409。错误返回JOB_TIMEOUT、NO_CANDIDATES、PLAN_INVALID、BUDGET_EXCEEDED、PROVIDER_UNAVAILABLE等稳定码，不暴露提供方正文。

## 日常协同过滤

先打通真实事件链：客户端只报view；favorite/unfavorite/trip_add由服务端成功事务产生，event_id去重；使用服务端接收时间，客户端时间仅参考。生产排除test、已注销用户、失效地点；撤销收藏从当前收藏状态消除正向信号，不重复累加刷权重。

推荐参数v1：最近90天，每用户每地点每天view最多计1、权重1；当前favorite权重3；trip_add去重后权重4。时间衰减半衰期30天；item-item余弦相似，至少3个共同用户，至少20名真实有效用户、100条有效交互才启用；个人至少3个有效地点，否则明确偏好兜底。参数是待真实数据评估的版本配置，不是证明有效的阈值。稀疏计算定时批处理，首版不增加向量数据库。

先过滤城市/类型/硬标签/价格单位等，再评分；硬标签all匹配，未知价格不满足硬价格上限。无法形成有效协同候选时使用fallback_preferences，最后fallback_catalog稳定排序；不得显示“大家都喜欢”以暗示不存在的人气。响应包含reason和algorithm_version。合成测试仅验证公式、去重、过滤和调用链；上线后才评估真实效果。

模型按城市独立发布与保留两版；读取必须匹配本次city_id，不套用全局或其他城市模型。SQL先应用城市、类型、标签与价格硬约束，再做协同聚合或偏好排序和结果限量，避免全国目录前1000条截断。每城市计算上限为10万条行为、10万条收藏和2000个有行为地点；超过保护上限需重新设计与验证，不宣称支持无限规模。发布时复查来源许可版本及用户状态，模型有效期不超过所用来源的复核期限。

## 伴游上下文

会话只能绑定本人行程。每次读取本人该会话当前用户序号之前成功完整轮次的最近20条消息，并限制总输入字符/模型token预算，附当前行程版本摘要；失败回复不作为模型回答历史。当前未删除的有效行程才提供背景，删除行程后关联置空，删除会话则消息不可读取。

message_id绑定内容摘要，成功重放同结果，不同内容409；同会话一次一轮pending/running，其他请求409。用户消息与回复槽位先持久化，租约回收防永久处理中；最后一轮失败可重试并复用槽位，不重复用户消息；存在后续用户轮次的旧失败轮不能原位重试。后台完成后客户端通过历史接口恢复结果。

地点事实从受控工具获取；未知明确告知，不虚构亲历。不支持聊天自动改行程/下订单，建议由用户回编辑页确认。模拟provider仅在dev/test启用且界面标明；生产拒绝模拟配置。

## 住宿计费与已保存行程编辑

住宿项目按一个入住夜记录：date为入住日，退房日隐含date+1，每项目计一晚，start_minute/end_minute均null，不占用白天游览时段。连续住同酒店两晚记录相邻两日两项；同日只能有一个住宿项目（即使不同酒店也拒绝），同一地点同日唯一约束仍保留。最后一晚的date必须早于trip.end_date，即退房日在行程日期范围内；单日行程不安排住宿。页面单独显示“当晚住宿”，不伪造入住/退房营业时间。当前模型已支持住宿分钟双NULL，并由迁移、约束及服务共同校验。

每晚价格从保存时每晚事实价取得；无有效每晚价格则成本未知或独立估算，不按两个日历日重复计费。预算按住宿夜数和非住宿项目计价单位合计。

新增/替换地点必须当前有效且同城，生成时所有候选都按当前目录验证；已有未替换项目保留快照和保存时价格，即使目录失效/涨价仍可读、重命名、删除或编辑其他项目，并显示状态/价格可能过期的警告。修改已有项目的时间/备注不自动刷新地点事实；替换place_id才生成新快照。首版不提供隐式“全部刷新事实”。

所有编辑检查归属、版本和受影响日期/时段的结构一致性；保留的失效地点不阻止整份行程编辑。标题/备注编辑与删除不因历史价格或未知成本失败；新增/替换项目及修改预算时用保留快照+新项目事实计算预算，已知下界超预算拒绝，未知警告。缩短日期导致任何保留项目（包括住宿退房日）越界则422，让用户先删除或调整；不静默丢弃。

协议字段、消息恢复、费用汇总和任务幂等以[接口业务不变量](../02接口与权限/数据传输结构.md)为准。模型调用中的assistant输出上限8000字符，发送接口处理截止45秒；客户端超时后通过消息状态恢复，不追加重复消息。

## 当前运行边界

当前仅有FakePlanner/FakeChat和disabled提供方。模拟规划不理解自由文本，模拟对话不提供真实旅游建议；正式模型需另做超时、工具调用、上下文与事实核验。推荐批处理由app.recommendation_batch执行，HTTP只读取已发布模型并计算本人的有界权重；模型失效、样本不足或计算上限触发时明确兜底。已引入13条CC0真实地点小样本，但没有用于效果验收的真实用户行为，当前不能评价推荐效果。来源到期、撤回或许可变更使模型失效；开发测试行为不能跨环境补充阈值。
