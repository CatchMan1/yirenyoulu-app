# 开发规范与发布准备

## 编码与架构

- 后端按auth、catalog、favorites、trips、planning、chat、recommendations划分业务模块；路由负责DTO和身份，服务负责规则与事务，仓储负责数据库访问。
- Python使用类型注解；ArkTS及TypeScript定义明确DTO，不使用any或强制转换掩盖接口差异。未知输入经过校验后再使用。
- 通用代码按实际复用需要提取，避免无业务需求的框架和微服务。函数、字段和错误码命名保持一致。
- 前端统一请求层处理超时、取消、200/201/202/204、令牌刷新及错误响应；页面提供加载、空数据、失败和重试状态。
- 写入事务提交成功后才返回成功；私有资源校验所有权，编辑校验版本。禁止记录密码、令牌、密钥和完整聊天正文。

## Git协作与检查

使用短功能分支，提交聚焦一项可审阅改动，经检查后合并。提交说明描述问题、变化和验证结果；保持已有远端工作，常规更新不强推。

提交前审阅差异，检查密钥、签名、数据库、个人数据和资源许可。仓库扫描覆盖工作树、暂存区及可达提交；忽略规则不能替代安全审查。依赖固定版本，结构变化使用新Alembic迁移。

自动检查覆盖后端测试、PostgreSQL迁移和契约，以及客户端类型、关键测试和构建。关键用例见[验收矩阵](../07测试与交付/验收矩阵.md)。没有运行的检查标记为未验证。

## 发布准备

记录发布提交、构建环境、SDK版本、迁移版本及验证结果。分别确认Apple/Huawei开发者主体、应用标识、签名和权限；准备隐私政策、支持渠道、注销与找回能力、SDK数据清单、授权图片及审核说明。

签名产物和密钥保存在受控存储，运行配置按环境注入。发布前核对平台当前要求及适用地区要求，并演练恢复和回滚流程。费用、账号开通和商业协议由项目负责人确认。
