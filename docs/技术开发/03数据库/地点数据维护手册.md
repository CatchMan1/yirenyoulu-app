# 地点数据维护手册

适用独立开发、测试及正式环境的地点库维护。当前采用人工执行，不自动启动定时任务、扩大额度、续期来源政策或开通付费服务。每次先核对目标环境、来源许可和资源预算；生产使用自己的凭据、权限和备份位置。

采集见[Wikidata运行指南](批量采集运行指南.md)与[Overture开放数据补充](酒店餐厅开放数据补充.md)，来源登记、审核及清理见[来源管理](地点数据导入与来源管理.md)。下列命令在仓库根目录执行，使用已配置的 `.env`；示例为 macOS/Linux，Windows 按对应虚拟环境路径和终端语法运行同一 Python 模块。

## 1. 人工操作周期

| 周期 | 操作 | 核对结果 |
|---|---|---|
| 每次采集或更新前 | 核对数据库、来源版本/许可/期限、累计额度；备份目标库；先预览少量候选 | 连接正确、备份可恢复、字段与状态映射在许可范围内；未知项不编造 |
| 每日或每次维护时 | 检查来源复核期限；按适用政策执行 `expire`；检查采集失败、额度及任务状态 | 到期来源不会继续提供事实；清理与备份保留符合来源要求 |
| 每周 | 生成城市质量报告；抽查新地点、字段缺口、旧资料及疑似重复；处理失败项 | 分清来源缺失、校验拒绝、待审核和未覆盖，不以总量代替质量 |
| 每月或上游发布新版本时 | 检查新版数据、许可和结构变化；新目录预览，再显式更新 | 既有ID保持稳定，停业证据明确，缺失不误停用，旧资料不覆盖新资料 |
| 推荐实际启用后每日 | 重算城市推荐模型，并在来源政策/地点事实变更后重新核对 | 记录城市、行为数、模型年龄与失败；行为不足允许兜底，不制造行为 |
| 定期及重要变更前 | 在隔离恢复库演练备份，核对迁移、行数和关键业务 | 备份可读取不等于已完整恢复；恢复库不开外部发送或付费服务 |

上述为当前维护建议，不是供应商承诺的更新频率。来源政策和范围许可到期前必须重新核实；`expire` 会清理已到期来源的事实和相关快照，执行前按来源条款确认备份及保留安排。读取端到期拒绝不依赖该命令先运行。

## 2. 数量和质量报告

```sh
PYTHONPATH=backend .venv/bin/python -m dotenv -f .env run --override -- .venv/bin/python -m app.data_operator coverage
PYTHONPATH=backend .venv/bin/python -m dotenv -f .env run --override -- .venv/bin/python -m app.data_operator quality --stale-days 30
```

Windows PowerShell 在项目根目录运行：

```powershell
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m dotenv -f .env run --override -- .\.venv\Scripts\python.exe -m app.data_operator quality --stale-days 30
```

其他命令沿用相同脚本与参数，将 Python 路径替换为 `.\.venv\Scripts\python.exe`，并使用 PowerShell 的单行或续行语法。本轮未在 Windows 实机验证。

`quality` 只看一个城市时增加 `--city CITY_UUID`，替换为 `cities.id`。`--stale-days` 支持1～3650天，默认30天。报告只读数据库，不请求外部来源。

`quality` 返回 `generated_at`、`stale_days`、`definitions` 与 `cities`；每个城市的 `groups` 固定包含三类地点，空组为0：

| 字段 | 解释 |
|---|---|
| `total`、`active`、`inactive`、`test_places` | 库存统计，包含测试和当前无权展示的记录；测试记录单独标记 |
| `display_eligible`、`computation_eligible` | 排除测试、失效及来源政策到期/撤回后，可展示与可计算的数量 |
| `missing` | 可展示地点中缺少坐标、地址、价格、营业时间、评分或可展示图片的数量；已知0元/0分不视作缺失 |
| `freshness.recent/stale/unknown/future` | 可展示地点按 `checked_at` 和阈值分类；未来时间单列，不当作新鲜资料 |
| `pending_duplicate_rows` | 该城市/类型仍待解决的疑似重复导入行数，不等于独立重复地点数量 |

`pending_duplicate_rows` 只统计已暂存的 `ImportRow`；Overture在入库前暂缓的候选另看导入输出 `held_for_duplicate_review` 和本地快照，不将这一项当作全部疑似重复。

字段缺失和新鲜度的分母仅为 `display_eligible`，不能用全部库存计算完整度。图片需自身展示资格及图片来源政策有效。观察时间表示来源资料时间，不证明今天营业、价格有效或实地核验；报告也不能推导全国覆盖率。

如需保存报告，存入受控、被 Git 忽略的位置；聚合报告不含用户数据，也不应连同数据库凭据上传公开仓库。

## 3. Overture持续更新

先核验上游版本、适用许可与字段结构，再使用新的输出目录。下面以 `2026-10-21.0` 演示语法，实际更新时换成已核验的新版本，并给目录使用同样的版本标识。

```sh
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py \
  --discover-cities \
  --release 2026-10-21.0 \
  --radius-km 30 \
  --tile-km 20 \
  --max-pages-per-tile 10 \
  --output-dir .local-data/overture/review-2026-10-21.0
```

不带 `--apply` 只下载候选，不更新地点库。查看快照、许可和报告后，保持同一版本、目录与范围，加上 `--refresh-existing --apply --env-file .env`；已下载页会重放到受控导入链路。同一时刻只运行一份任务。新版本、范围或目录配置变化不得混用原快照；遇到配置不一致应停止核对。

也可先预览单个已下载快照：

```sh
PYTHONPATH=backend .venv/bin/python scripts/import_overture.py \
  --snapshot .local-data/overture/review-2026-10-21.0/Q956-00015-t0000-p0000.json \
  --catalog .local-data/overture/review-2026-10-21.0/cities.json \
  --refresh-existing \
  --env-file .env
```

文件名以实际下载结果为准。核对后增加 `--apply`；去掉 `--refresh-existing` 则仍用于首次铺入和失败补跑，已有同源ID跳过。

更新规则：

- 保持内部UUID，通过来源和外部ID更新已有同城、同类地点；城市/类型冲突拒绝，不静默迁移。
- 观察时间采用快照版本日期，不用文件修改时间或复制日期；旧版本不覆盖较新事实。同一版本重跑不应人为刷新新鲜度。
- 只有已入库同源地点、经原有许可/城市/类型/坐标校验且来源明确 `permanently_closed` 时，才置为 `inactive`。新ID的关闭记录不新增。
- 临时关闭、未知状态、某页缺少或某次查询没有该地点，不作为永久关闭证据，也不删除记录。已有停用地点不会因未知状态重新启用；后续版本明确 `open` 且通过校验才恢复。
- 普通地点更新保留行程地点快照；来源撤权或存储资格变化另走来源清理流程。

停业状态属于 `status` 字段。已有来源政策如未授权该字段，应按实际许可复核，用 `app.data_operator source --file ...` 更新白名单后重新审核；来源名称必须与现有记录完全一致，保留仍获准的原字段，仅补入已核验的 `status`。白名单收缩会触发整来源事实清理，不能为了补状态而删去其他字段。程序不会自动扩字段、续期或清零预算。已有范围许可省略 `--max-records` 时保持原上限；显式调整上限也不重置已用量或有效期。来源配置格式见[来源管理第3节](地点数据导入与来源管理.md#3-登记来源政策)，不得直接改数据库以绕过限制。

## 4. 其他维护命令

```sh
# 根据当前政策处理已到期来源；此操作会写库和清理来源事实。
PYTHONPATH=backend .venv/bin/python -m dotenv -f .env run --override -- .venv/bin/python -m app.data_operator expire
# 重新构建各城市的推荐模型；缺少真实行为时保留兜底。
PYTHONPATH=backend .venv/bin/python -m dotenv -f .env run --override -- .venv/bin/python -m app.recommendation_batch
```

政策更新后旧批次可能因版本不一致拒绝应用，应按新许可重新暂存、审核，不手改游标或批次状态。Wikidata已完成任务需获取新事实时，使用新的 `run_key`；恢复旧任务使用原 `run_id`，详情见[批量采集运行指南](批量采集运行指南.md#6-中断续跑与更新)。

## 5. 失败恢复、备份和文件保留

先读报告区分下载失败、入库失败、许可到期、预算耗尽与重复待审，再修复对应原因。网络中断后复用同目录和参数；已经成功入库的行保留。达到网格页数或下载上限会报告未完成，不能据此宣称整城已采全。不要并行重开任务绕过限速和额度，也不要用新任务键重置累计计数。

备份与隔离恢复方法见[迁移与备份恢复](迁移与备份恢复.md)。从另一电脑迁入数据前先备份，确认迁移版本、来源政策、观测时间、唯一标识与目标库一致；数据导入后再跑质量报告和业务抽查。

本地快照、日志和报告按来源允许范围及实际维护需求保留；备份采用受控位置和适用的加密、访问及保留规则。清理采集目录前先停止采集进程，并确认不再需要断点恢复；删除快照不删除数据库地点，但会失去本地下载检查点。数据库 `purge` 不会删除这些文件或旧备份，必须分别处理。
