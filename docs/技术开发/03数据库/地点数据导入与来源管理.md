# 地点数据导入与来源管理

本文供后端开发者和有数据库操作权限的运营人员使用。导入入口为本地命令 `app.data_operator`，不提供面向用户、客户端或 Agent 的导入、审批和任意 SQL 接口。原项目资料只作参考，所有操作必须连接新版项目的独立数据库。

来源选择与必需事实见[数据来源与导入设计](数据来源与导入设计.md)，数据库初始化、备份和恢复见[迁移与备份恢复](迁移与备份恢复.md)。本文命令在新版仓库根目录执行。

## 1. 当前来源与使用边界

| 来源 | 当前支持 | 使用条件 |
|---|---|---|
| Wikidata 结构化数据 | 通过官方 API 按明确 QID 读取少量地点及城市归属证据 | 核验 CC0 适用范围、记录来源政策，再登记城市和数量许可；不包含照片或维基百科正文 |
| OpenStreetMap | 将已有、获准使用的离线 JSON 映射为候选 manifest | 当前没有在线采集器；ODbL、署名、数据库共享及商业使用安排确认前不采集、不导入真实样本 |
| 高德、Google 等地图数据 | 未提供正式地点采集器 | API 调用权限与商业展示、存储、更新权限分别核验，不能凭地图 Key 导入长期数据库 |

本期真实采样仅使用许可已核验的 Wikidata 结构化数据。官方依据为 [Wikidata 数据访问](https://www.wikidata.org/wiki/Wikidata:Data_access)、[许可说明](https://www.wikidata.org/wiki/Wikidata:Licensing)和 [Wikibase API](https://www.mediawiki.org/wiki/Wikibase/API)。登记政策只是记录已取得的权利，不会向供应商申请许可或自动取得商业授权。

城市映射和导入批次支持逐步增加覆盖范围。现有命令不枚举全国地点，不支持无限采集，也不以城市数量或样本数量证明数据完整性。

## 2. 操作环境与本地文件

先按运行文档配置独立虚拟环境、环境变量并完成 Alembic 迁移。应用不自动读取 `.env`；由受信任的本地环境管理方式注入 `APP_ENV`、`DATABASE_URL` 和所需配置。库名与环境必须匹配：开发为 `yirenyoulu_dev`，测试为 `yirenyoulu_test`，生产为 `yirenyoulu_prod`。

```sh
PYTHONPATH=backend .venv/bin/python -m app.data_operator --help
```

原始响应、候选 manifest、审核记录和操作报告放在仓库根目录的 `.local-data/` 等本地隔离目录中，该目录必须被 Git 忽略。不要把来源载荷、用户信息、数据库文件、连接凭据或签名材料提交到仓库。CLI 新建输出文件使用仅当前用户可读写的权限，并拒绝覆盖已有同名文件；再次获取时改用新文件名。

以下示例中的 `SOURCE_ID`、`CITY_ID`、`BATCH_ID`、`ROW_ID`、`PLACE_ID` 都要替换为命令返回的真实标识。示例文件名和审核引用不是审批凭证。

## 3. 登记来源政策

在 `.local-data/source-wikidata.json` 保存政策配置。`evidence` 填写实际许可核验记录的引用、核验日期及适用范围，不得保留示例占位内容。

```json
{
  "name": "Wikidata-CC0",
  "license_url": "https://creativecommons.org/publicdomain/zero/1.0/",
  "evidence": "<实际许可核验记录编号、日期、官方依据和结构化字段适用范围>",
  "allowed_fields": [
    "external_id", "kind", "name", "source_url", "observed_at",
    "status", "coordinates", "evidence", "currency"
  ],
  "computation_allowed": true,
  "days": 30
}
```

```sh
PYTHONPATH=backend .venv/bin/python -m app.data_operator source --file .local-data/source-wikidata.json
```

| 字段 | 含义与操作要求 |
|---|---|
| `name` | 来源的稳定名称；同名再次登记会更新政策，并使版本递增 |
| `license_url`、`evidence` | 公开许可入口与实际核验依据；URL 必须为不含查询参数、用户凭据或片段的公开 HTTPS 地址 |
| `allowed_fields` | 允许存储的 `PlaceRecord` 字段白名单；未知字段拒绝。只校验实际提供的来源字段，DTO内部默认值不视作来源证据；未经许可的显式字段仍拒绝 |
| `computation_allowed` | 是否允许进入Agent规划及推荐的候选与计算；仅有展示权不会自动获得计算许可 |
| `days` | 本系统的政策复核期限，默认 30 天、允许 1～365 天；这不是对外部许可期限的法律判断 |

政策登记会记录存储、商业展示审核状态和期限；撤回或到期时读取端立即停止提供相关资料。更新政策会使现有推荐模型过期，旧批次绑定的政策版本不能继续套用；应按新政策重新整理候选并暂存。字段白名单收缩时，系统保守清理整个来源的旧事实、暂存载荷和历史快照，并停用地点；即使仍获准的事实也需重新审核导入后恢复。

示例仅授权当前 Wikidata 映射会输出的字段。其余可选字段需有相应证据，并加入白名单后才可使用：`description`、`address`、`price_minor`、`price_unit`、`price_conditions`、`hotel_stars`、`cuisine`、`category`、`tags`、`opening_hours`。`currency` 是 DTO 的计价币种默认值，不能把它当作来源已提供价格的证据。价格为空时不会生成价格事实。

照片和评分不在当前导入 DTO 中。不要将图片链接塞入描述或 `evidence` 来绕过独立图片授权。

## 4. 登记城市与累计许可

城市使用内部 UUID 作为业务 ID，来源城市编号另存 `CityAlias`。不要把国家统计代码、供应商行政区代码和 Wikidata QID 混成同一种 ID。

`.local-data/city-beijing.json` 示例：

```json
{
  "namespace": "wikidata",
  "external_id": "Q956",
  "name": "北京市",
  "parent_code": null
}
```

```sh
PYTHONPATH=backend .venv/bin/python -m app.data_operator city --file .local-data/city-beijing.json
PYTHONPATH=backend .venv/bin/python -m app.data_operator permit --source SOURCE_ID --cities CITY_ID --limit 30 --reference '实际范围审批记录编号'
```

同一 `namespace + external_id` 重复登记返回原城市 ID，内部城市代码采用 `namespace:external_id`；显示名称不能用作稳定关联键。多个城市用 `--cities CITY_ID_1,CITY_ID_2`，每个城市须先登记。当前登记城市统一使用 `Asia/Shanghai` 时区，采样适用中国大陆城市。

数量许可与来源政策分开管理：政策回答能否使用，许可回答本次批准处理哪些城市、累计多少条。CLI 当前签发的许可有效期为 7 天；`--limit` 是该来源的累计记录上限，不是每批上限。同源新批次按输入行数消耗额度，包含后续被拒绝的行；完全相同的批次键和内容重放不重复计数。变更许可不清零已用额度，也不能把上限降到已用数量以下。

网络请求预算独立计数，当前默认每来源累计最多 30 次。每次请求尝试在发出前持久扣减，失败与重试也计数；重新执行 `permit` 不重置请求计数。CLI 没有无限额或自动扩额参数。超过范围、期限或额度应停止操作，重新确认范围及实现限制后处理。

## 5. 获取、暂存、报告、审核、应用

### 5.1 获取少量明确实体

以下命令以北京城市 QID 和一个明确地点 QID 演示。运行前必须确认来源政策、城市映射和本次范围已获准。

```sh
PYTHONPATH=backend .venv/bin/python -m app.data_operator fetch --source SOURCE_ID --city CITY_ID --city-qid Q956 --kind attraction --ids Q80290 --output .local-data/beijing-attraction-manifest.json
```

`kind` 仅支持 `attraction`、`hotel`、`restaurant`。一次 `fetch` 的城市 QID 与地点 QID 合计最多 25 个；多个地点用英文逗号分隔。适配器还会在预算内补读行政区父链，不能把地点数量直接等同于请求次数。

连接器只访问固定的 Wikidata 官方 API，不接受任意 URL，不跟随跳转。连接超时为 5 秒，其余 I/O 阶段超时为 15 秒，解压后响应上限 3 MB，单次实体查询最多尝试 3 次；429、部分 5xx 和 `maxlag` 有限等待重试。`Retry-After` 不能在短等待范围内满足时停止，留待稍后处理，不持续抢占服务。

映射要求城市具有中国归属证据，地点具有可支持的明确类型，且行政区链能够到达目标城市。类型不支持、跨城市、证据缺失的条目进入输出的 `rejected`，不会猜城市或强行改分类。输出文件有拒绝条目时，应先查看原因和来源事实，再决定后续处理。

Wikidata 坐标只接受地球坐标中的单一有效最佳值，并标记 `WGS84`；竞争值、非地球值或缺失值不任选其一。资料中没有关闭证据而标记为 `active`，仅表示当前记录可参与业务候选，不表示已核验今天营业或可预约。

### 5.2 Manifest 结构

`fetch` 输出包含 `source_id`、`city_id`、`kind`、`records`、`rejected` 和 `fetched_at`。`stage` 会核对前三项与命令参数一致，只处理 `records`；获取阶段的 `rejected` 不会自动计入后续批次报告，应连同原 manifest 留在私有审核记录中。

以下仅为格式演示，不能作为真实资料导入：

```json
{
  "source_id": "SOURCE_ID",
  "city_id": "CITY_ID",
  "kind": "attraction",
  "records": [
    {
      "external_id": "EXAMPLE-DO-NOT-IMPORT",
      "kind": "attraction",
      "name": "示例地点（仅结构演示）",
      "source_url": "https://example.org/places/example",
      "observed_at": "2026-01-01T00:00:00Z",
      "coordinates": null,
      "status": "active",
      "evidence": {}
    }
  ],
  "rejected": [],
  "fetched_at": "2026-01-01T00:00:00Z"
}
```

也可使用纯记录数组，但建议保留 manifest 的来源和城市边界。每份输入文件最多读取 10 MB，每批 1～500 行。`observed_at` 必须带时区，不能超前当前时间 5 分钟以上。

### 5.3 暂存与人工审核

```sh
PYTHONPATH=backend .venv/bin/python -m app.data_operator stage --source SOURCE_ID --city CITY_ID --kind attraction --key beijing-attraction-review-001 --file .local-data/beijing-attraction-manifest.json
PYTHONPATH=backend .venv/bin/python -m app.data_operator report --batch BATCH_ID
PYTHONPATH=backend .venv/bin/python -m app.data_operator approve --batch BATCH_ID --reference '实际样本审核记录编号'
PYTHONPATH=backend .venv/bin/python -m app.data_operator apply --batch BATCH_ID --limit 10
PYTHONPATH=backend .venv/bin/python -m app.data_operator report --batch BATCH_ID
```

`stage` 将候选隔离保存，不创建可浏览地点。未知字段、越界坐标、价格条件不全、同批重复外部 ID 等行会变为 `rejected`，只保存安全错误码，不保留无效载荷。审核应检查来源证据、城市、类型、名称、缺失字段以及样本是否符合本次范围。`approve` 记录人工审核引用，不能替代核对。

`apply` 才将已审核的有效行写入地点库。每行地点、外部 ID、字段来源和检查点在同一事务提交；某行失败则该行全部回滚，之前成功提交的行保留。`--limit 10` 只推进最多 10 个批次行，包括拒绝或跳过的行；省略时处理至完成或遇到失败。

批次状态为 `staged → approved → completed`，处理失败可记为 `failed`。报告同时提供 `total`、`cursor`、`last_error`，以及 `validated`、`rejected`、`duplicate`、`applied`、`skipped` 的行数。`completed` 表示所有行已检查，不能据此声称所有地点都已导入；拒绝和疑似重复必须分别核对。

### 5.4 断点恢复与幂等

```sh
PYTHONPATH=backend .venv/bin/python -m app.data_operator report --batch BATCH_ID
PYTHONPATH=backend .venv/bin/python -m app.data_operator apply --batch BATCH_ID
```

恢复时复用原 `BATCH_ID`，从持久化 `cursor` 继续。可恢复的分类/标签配置错误在修正后重试，已提交行不会重复插入；数据库完全不可用时可能无法写入失败状态，应先恢复连接再查检查点。

同来源的 `--key` 唯一关联输入摘要、城市和类型。原输入不变时重复 `stage` 返回原批次；同键改内容会报幂等冲突。来源政策版本变更必须按新政策重新暂存，并使用新键。不要为了绕开报错修改数据库中的批次状态、摘要或游标。

## 6. 去重、更新与字段可信度

| 情况 | 实际行为 |
|---|---|
| 同来源、同外部 ID | 更新原地点，内部 UUID 不变；城市或类型发生冲突时拒绝 |
| 较旧 `observed_at` 再导入 | 标记 `skipped / OLDER_OBSERVATION`，不覆盖较新资料 |
| 同城市、同类型、跨来源规范化名称摘要相同 | 标记 `duplicate / CROSS_SOURCE_REVIEW_REQUIRED`，等待人工核实；名称比较只找候选，不自动合并 |
| 已人工确认的跨来源别名 | 只维护别名对应的来源观察时间，不覆盖主来源事实 |
| 新快照缺少原有可选事实 | 按完整快照语义改为未知，不保留已被来源移除的旧价格或坐标 |

疑似重复可能到 `apply` 时才发现。用 `report` 取得 `ROW_ID` 后，对照目标地点的城市、类别、地址和位置证据核实是否为同一实体；只有确认相同时才登记别名：

```sh
PYTHONPATH=backend .venv/bin/python -m app.data_operator resolve --row ROW_ID --place PLACE_ID --reference '实际重复核验记录编号'
```

无法确认，或名称相同但实际不同的地点，继续保留隔离，不强制归并。当前 CLI 不提供“忽略重复直接新建”的入口，也没有一般性的手工字段覆盖入口。

坐标必须保存经度、纬度和 `WGS84`、`GCJ-02`、`BD09` 之一的坐标系。禁止只改坐标系标签而不转换数值；地图适配端按源坐标系转换和展示。无坐标地点仍可供文字浏览，但不表示已通过地图或路径验收。

金额使用整数最小货币单位 `price_minor`，需同时给出 `price_unit` 和可展示的 `price_conditions`：景点为 `entry`，酒店为 `night`，餐厅为 `person`，币种当前仅支持 CNY。日期、票种、房型或适用人群等价格前提写入条件。未知价格为 `null`，不能填 0；0 只用于来源明确确认的免费条件。缺少价格的地点不会被硬价格筛选当作免费地点。

营业时间必须符合接口约定的结构；OSM 原始营业时间文本只保留在证据中，未自动转成可营业判断。酒店星级和餐厅菜系限制在对应类型使用。分类和标签引用已登记的稳定代码，不因来源文本自动创建任意分类。

`PlaceFieldProvenance` 记录字段来源、外部 ID、观察时间、缺失原因及必要证据。当前导入器不接受估算金额、评分推断或模型编造的营业时间；如规划器给出估算，应进入专门估算结构并明确展示，不回写为地点事实。地点更新通常不修改已保存的行程地点快照；来源撤权涉及快照隐藏或清理，是单独的权利处理流程。

## 7. 撤回、清理与到期

```sh
PYTHONPATH=backend .venv/bin/python -m app.data_operator revoke --source SOURCE_ID
PYTHONPATH=backend .venv/bin/python -m app.data_operator purge --source SOURCE_ID
PYTHONPATH=backend .venv/bin/python -m app.data_operator expire
```

- `revoke`：撤回来源展示资格并使推荐模型过期；目录、详情、Agent 工具和推荐读取按当前来源权利过滤，收藏和行程响应隐藏相关事实。
- `purge`：包含撤回，同时清理该主来源地点的名称、地址、坐标、价格等事实，停用地点，移除相应图片、标签和字段证据，清空该来源暂存载荷，并清理对应行程快照事实。
- `expire`：寻找政策已到期的来源，执行撤回与事实清理；重复运行不会重新导入资料。读取端的到期拒绝不依赖此命令先运行。

到期清理会在锁内复查期限，避免与来源续期竞争而误清理。当前没有自动运行的到期任务。部署方应将 `expire` 纳入受控定时任务并监控执行结果；本地文件、备份和恢复副本也需遵守对应期限。数据库清理不自动删除私有目录中的原始文件或既有备份。

清理仍保留内部标识、外部 ID、来源 URL/观察时间、批次摘要和审核引用等最小关联及审计信息。如来源要求这些内容也删除，应先核对要求并补充清理范围，不能把现有 `purge` 等同于任何协议下的完整销毁。清理前按适用政策确认备份和恢复安排。

恢复来源需要重新核验并登记政策；被清空的事实不会自行恢复，仍需新的候选批次、审核与应用。

## 8. 覆盖报告与业务验证

```sh
PYTHONPATH=backend .venv/bin/python -m app.data_operator coverage
```

覆盖报告按城市与地点类型统计当前有效、允许展示的地点；它不代表价格、营业时间或坐标齐全，也不代表城市覆盖完整。开发/测试库若含 fixture，统计可能包含明确标记的虚拟地点；真实样本验收使用隔离数据库或单独核对来源。

导入后应验证城市筛选、浏览、搜索、详情、收藏、行程地点保存、规划工具查询、未知价格处理和来源撤回。协同推荐计算还需独立的真实行为链路；真实地点入库不会生成用户行为，测试账户行为不能用来宣称个性化效果。地图 SDK、真实模型、客户端联调和生产部署分别验收，不能用导入报告代替。

## 9. 常见停止原因

| 现象或内部错误码 | 处理 |
|---|---|
| `SOURCE_NOT_AUTHORIZED`、`REAL_SOURCE_POLICY_REQUIRED` | 核对来源类型、真实许可核验、期限和撤回状态 |
| `PERMIT_REQUIRED`、`PERMIT_EXHAUSTED`、`REQUEST_BUDGET_EXHAUSTED` | 停止扩大范围；核对城市、有效期及累计消耗，按已批准范围处理 |
| `MANIFEST_SCOPE_MISMATCH` | 核对文件中的来源、城市、类型与命令参数，不手改归属冒充正确证据 |
| `INVALID_RECORD` | 检查原 manifest 与 DTO：字段授权、空值、单位、坐标及时间；修正后以新输入批次处理 |
| `POLICY_CHANGED_RESTAGE`、幂等冲突 | 按新政策或新内容生成新批次键，不修改原批次证据 |
| `CATEGORY_NOT_REGISTERED`、`TAG_NOT_REGISTERED` | 补充经确认的基础分类/标签或修正输入；事务失败的批次可按原检查点恢复 |
| `PROVIDER_RETRY_LATER`、`PROVIDER_UNAVAILABLE` | 检查额度和服务状态，稍后有限重试；不改为未审核供应商或付费接口 |
| `STORAGE_UNAVAILABLE` | 检查独立数据库与迁移状态，恢复后先查批次报告 |

CLI 会以安全摘要结束失败操作，不回显来源载荷或连接凭据；部分内部原因通过批次 `last_error` 或行级 `error` 查看。排错时不要把私有配置、完整响应或数据库连接字符串粘贴到公开 issue。
