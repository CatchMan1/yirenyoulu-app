# 酒店与餐厅开放数据补充

使用 Overture Maps Places `2026-10-21.0` 公开快照，补充 Wikidata 酒店、餐饮覆盖。当前范围为北京、上海、广州各约 0.1°×0.1°的中心区域，不代表整座城市。OSM 尚未接入正式地点库。

## 来源和许可

来源与说明：[Places](https://docs.overturemaps.org/guides/places/)、[许可与署名](https://docs.overturemaps.org/attribution/)。仅接受记录中明确标记 `CDLA-Permissive-2.0`、`Apache-2.0` 或 `CC0-1.0` 的来源。每条保留原始来源、许可、版本和外部 ID；展示端应保留 Overture 及适用上游来源署名，数据分发时随附适用许可证及通知。

许可原文：[CDLA-Permissive-2.0](https://cdla.dev/permissive-2-0/)、[Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0)、[CC0-1.0](https://creativecommons.org/publicdomain/zero/1.0/)。不获取照片、点评、实时房价或用户个人联系方式。下载无需供应商密钥或付费账号；本机网络、磁盘和计算仍有资源消耗。

## 下载

在仓库根目录安装可选数据依赖并安装 DuckDB 官方 HTTP 扩展：

```sh
.venv/bin/python -m pip install -r backend/requirements-data.txt
.venv/bin/python -c "import duckdb; duckdb.connect().execute('INSTALL httpfs')"
PYTHONPATH=backend .venv/bin/python scripts/collect_overture.py --city beijing --output .local-data/overture/beijing.json
```

城市可选 `beijing`、`shanghai`、`guangzhou`。一次运行一个城市，完成后再运行下一个。输出已存在时拒绝覆盖，后续直接使用已下载文件。

网络请求经本机回环中转串行转发至固定公开文件：请求开始至少间隔 2 秒，响应读取节流约 512 KiB/s，每城最多 300 次请求、128 MiB 响应体及 2,000 个候选。查询中断期限 15 分钟，正在进行的网络操作还受 30 秒超时约束。限制是本地保护值，不是提供方额度；中断不会发布部分输出文件。无需把回环端口开放到外网。

## 预览与入库

开发数据库启动并完成迁移后，先预览：

```sh
PYTHONPATH=backend .venv/bin/python scripts/import_overture.py --snapshot .local-data/overture/beijing.json --env-file .env
```

备份数据库后，显式加 `--apply`：

```sh
PYTHONPATH=backend .venv/bin/python scripts/import_overture.py --snapshot .local-data/overture/beijing.json --env-file .env --apply
```

每次最多各导入 30 条酒店、餐厅。重复执行会从尚未入库、通过去重的候选中继续选择；相同外部 ID 不重复新增。来源初次建立有限期政策和 1,000 条记录许可，之后不自动续期或重置消耗。

验证要求：中国地址、明确城市名匹配、点坐标位于配置范围、已审许可、置信度至少 0.8、类别层级属于酒店或餐厅。坐标来自 WKB 点几何，索引 bbox 仅供范围检查。来源置信度不是用户评分，也不证明商家当前营业。

未知营业状态保留在来源证据中；`active` 表示目录记录有效，不表示“当前营业”。已明确停业的候选不导入。价格、评分、营业时间、图片缺失时保持未知。

同名地点或相近的同类地点（酒店 200 米、餐厅 30 米以内）暂缓入库，保留在原始快照供人工复核。相近不等于同一家，因此不自动合并；此策略可能暂缓不同商家。跨语言、远距离坐标错误等情况仍需人工抽查，不能宣称已完全去重或核验实地营业。

原始快照、备份和本地环境文件位于忽略目录，不提交 GitHub。推荐只将通过来源权限检查的有效地点提供给推荐和行程规划；用户行为仍须来自真实业务，不能用采集记录代替。

## 一条命令遍历城市目录

在项目根目录运行（先安装 `backend/requirements-data.txt` 中的可选依赖）：

```bash
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py
```

默认读取 `.local-data/wikidata-country.json` 中的城市 ID，查询 Wikidata 的城市名称和地球坐标，生成 `.local-data/overture/country/cities.json`。其中 `names` 保存英文与中文名称；文件使用稳定 QID 命名，避免英文重名造成覆盖。该目录是城市候选清单，不是完整行政区划名录。缺失或有歧义的坐标不会猜测，列入 `skipped`。

随后串行采集各城市酒店、餐厅候选，按坐标选择 Overture 数据分区。每个城市中心经纬度各向外 0.05 度，每个相交分区最多 2,000 条；这是中心区域样本，不是全市覆盖，也不保证下载数量等于可入库数量。会重复查询尚未完成的城市；已完成且配置匹配的文件自动跳过。Ctrl+C 停止后重新运行相同命令即可继续。网络恢复后也可重新运行失败项。不要同时启动多份命令，也不要修改已开始任务的城市名单；需要更换名单时用新的 `--output-dir`。

仅生成名单、不下载地点：

```bash
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py --prepare-only
```

结果保存在 `.local-data/overture/country/`：

- `cities.json`：城市名称、坐标范围、跳过项。
- `Q编号-分区编号.json`：各城市候选地点，含来源和版本。
- `report.json`：任务结束报告，失败或跳过项不为空时退出码为 1。

元数据请求至少间隔 2 秒，失败最多尝试 3 次；地点下载沿用原下载器的请求间隔、流量和超时限制，城市分区之间再间隔 10 秒。全国任务可能持续很久，保持网络连接和电脑唤醒。不会自动启动数据库或写入数据库。

## 采集后自动入库

先启动 PostgreSQL，并确认项目根目录 `.env` 指向新版本开发数据库。在项目根目录运行：

```bash
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py --apply --env-file .env
```

每个快照下载完成后自动执行来源许可、地点类型、城市、坐标、置信度校验和去重，再分批入库。已下载文件也会补做入库，不会因为跳过下载而遗漏。缺少的城市按目录中的 Wikidata ID 注册，已有城市不改名。候选记录可能被拒绝或留待重复检查；查看 `rejected`、`held_for_duplicate_review`、`already_imported` 及批次 `applied` 数量，不要把下载数量当作入库数量。单个文件失败会在报告中列出，其他文件继续。

只导入已经下载的全国文件，不访问网络：

```bash
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py --import-only --apply --env-file .env
```

以上命令使用 `.local-data/overture/country/cities.json` 与该目录下 `Q编号-分区编号.json` 文件。使用自定义目录时附加 `--output-dir 路径`。仅运行不带 `--apply` 的原命令仍然只下载。

先预览一个全国快照：

```bash
PYTHONPATH=backend .venv/bin/python scripts/import_overture.py --snapshot .local-data/overture/country/Q956-00015.json --catalog .local-data/overture/country/cities.json --env-file .env
```

预览不写数据库；上述文件名以实际下载结果为准。全国导入不会再限制每类 30 条，但保留每个快照最多 2,000 条候选及来源累计额度。`--max-records` 默认为 100000，可设置 1 至 100000；它是来源的累计导入额度，不是每次新增额度，也不是提供方免费配额。首次申请许可有效期为 7 天，扩大城市范围或调整额度不延长已有许可有效期、不重置已用量。额度不足、许可过期或撤销时入库失败，已有数据保留；需按来源管理流程处理后重跑。

重复执行会跳过已存在的来源外部 ID。本命令用于首次铺入和失败补跑，不用于刷新已入库地点事实。每条记录沿用事务及批次状态管理，整个全国任务不是一个大事务，中断前已成功入库的记录保留。不要同时运行多个全国导入进程。原三城市入库命令不带 `--catalog` 时仍保持每类 30 条的样本限制。

## 扩大范围并补充全国城市候选

需要增加酒店、餐厅覆盖时，在项目根目录运行：

```bash
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py \
  --discover-cities \
  --radius-km 30 \
  --tile-km 20 \
  --max-pages-per-tile 10 \
  --output-dir .local-data/overture/country-r30 \
  --apply \
  --env-file .env
```

先启动开发数据库；程序不会自行启动 Docker。命令不需要 API、手机 App 或付费账号。

| 参数 | 含义 |
|---|---|
| `--discover-cities` | 从 Wikidata 固定中国城市查询分页发现候选，与现有城市名单合并。保留下级城市候选，不再只使用父级城市目录。最多 5,000 个候选，发现失败时停止，不把不完整目录当成完整名单 |
| `--radius-km 30` | 查询城市中心到矩形四边约 30 公里的范围；矩形约 60 × 60 公里，角点距离中心更远。这是搜索范围，不是行政区边界或严格圆形；允许 1～100 公里 |
| `--tile-km 20` | 将矩形分成边长不超过约 20 公里的网格，允许 5～50 公里。分块处理减少单次查询的数据量 |
| `--max-pages-per-tile 10` | 每个网格和相交数据分区最多 10 页，每页最多 2,000 个酒店/餐厅候选。按稳定地点 ID 排序并使用排他游标，不把满页当作结束 |
| `--max-new-pages` | 单次运行最多新尝试的地点页数，默认 1000，允许 1～100000；失败下载也计数，缓存页面不计数。达到上限报告未完成，重复运行同一命令继续 |
| `--output-dir` | 扩围任务使用新目录，保留原 `.local-data/overture/country/` 文件；同目录的版本、城市名单、公里范围和网格配置必须一致 |
| `--apply --env-file .env` | 下载每页后执行现有校验、去重、受控入库；同源已入库 ID 跳过。累计来源额度仍由 `--max-records` 限制 |

同一命令重跑会复用城市发现检查点、已准备成功的城市及已完成的地点页，并重试未准备成功的城市。每页继续沿用至少 2 秒请求间隔、约 512 KiB/s 读取节流、最多 300 个请求、128 MiB 响应和 15 分钟查询时限，新下载页之间间隔 10 秒；这些是每页本地保护值，全国累计耗时和流量会增加，不是供应商免费额度。保持电脑唤醒和网络稳定，不并行启动同一任务。

如果报告 `limited_tiles` 不为空，说明有网格达到页数上限，任务还未完成。可使用相同目录、相同范围和网格，把 `--max-pages-per-tile` 提高到 20（最高 100）后重跑，已有页面不会重下。`failed`、`limited_tiles` 或 `skipped` 任一不为空时退出码为 1；不能以命令停止或已有文件判断全国采集完整。

只生成扩大后的城市目录、不下载地点、不入库：

```bash
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py \
  --discover-cities --radius-km 30 --tile-km 20 \
  --output-dir .local-data/overture/country-r30 --prepare-only
```

只补做这个目录的入库：

```bash
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py \
  --output-dir .local-data/overture/country-r30 \
  --import-only --apply --env-file .env
```

新地点文件按 `Q编号-分区-t网格号-p页号.json` 命名，`cities.json` 保存城市范围，`city-discovery.json` 保存城市发现游标，`report.json` 列出失败/跳过和触顶网格。页内记录仍须通过中国地址、城市名称、坐标及许可校验，邻近城市或郊区地址未能匹配不会强行归属。Wikidata 不是官方完整行政区名录；目录无城市、无可靠中心坐标、城市名称无法匹配或 Overture 无资料的情况会留下覆盖缺口，不保证全国每个城市都有数据。

本参数扩展酒店和餐厅采集，景点仍使用 Wikidata 采集入口。正式扩大采集后的数量和覆盖率，需要运行结束后查询数据库并抽查；离线测试通过不代表已验证全国真实数据覆盖。

若 `limited_tiles` 中出现 `download_limit`，表示达到本次新下载页数保护，重跑原命令即可继续。此计数是单次运行的查询页数，不是来源记录累计额度，也不代表供应商配额。

## 本地采集文件清理

地点以 PostgreSQL 为持久数据源。本地 `.local-data/` 只保存下载快照、目录和续跑信息；清理前先停止采集进程，确认所需记录已入库。删除目录后无法继续旧文件游标，可使用本文 `--discover-cities` 命令重新发现目录并采集，数据库中的同源外部 ID 仍会去重。不要删除 Docker 数据卷。生产备份应单独保存在受控备份位置。
