# 酒店与餐厅开放数据补充

使用 Overture Maps Places `2026-10-21.0` 公开快照，补充 Wikidata 酒店、餐饮覆盖。当前范围为北京、上海、广州各约 0.1°×0.1°的中心区域，不代表整座城市。OSM 尚未接入正式地点库。

## 来源和许可

来源与说明：[Places](https://docs.overturemaps.org/guides/places/)、[许可与署名](https://docs.overturemaps.org/attribution/)。仅接受记录中明确标记 `CDLA-Permissive-2.0`、`Apache-2.0` 或 `CC0-1.0` 的来源。每条保留原始来源、许可、版本和外部 ID；展示端应保留 Overture 及适用上游来源署名，数据分发时随附适用许可证及通知。

许可原文：[CDLA-Permissive-2.0](https://cdla.dev/permissive-2-0/)、[Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0)、[CC0-1.0](https://creativecommons.org/publicdomain/zero/1.0/)。不获取照片、点评、实时房价或用户个人联系方式。下载无需供应商密钥或付费账号；本机网络、磁盘和计算仍有资源消耗。

## 下载

在仓库根目录安装可选数据依赖并安装 DuckDB 官方 HTTP 扩展：

```sh
.venv/bin/python -m pip install -r backend/requirements-data.txt
.venv/bin/python -c "import duckdb; duckdb.connect().execute('INSTALL httpfs')"
PYTHONPATH=backend .venv/bin/python scripts/collect_overture.py --city beijing --output .local-data/overture/beijing.json
```

城市可选 `beijing`、`shanghai`、`guangzhou`。一次运行一个城市，完成后再运行下一个。输出已存在时拒绝覆盖，后续直接使用已下载文件。

网络请求经本机回环中转串行转发至固定公开文件：请求开始至少间隔 2 秒，响应读取节流约 512 KiB/s，每城最多 300 次请求、128 MiB 响应体及 2,000 个候选。查询中断期限 15 分钟，正在进行的网络操作还受 30 秒超时约束。限制是本地保护值，不是提供方额度；中断不会发布部分输出文件。无需把回环端口开放到外网。

## 预览与入库

开发数据库启动并完成迁移后，先预览：

```sh
PYTHONPATH=backend .venv/bin/python scripts/import_overture.py --snapshot .local-data/overture/beijing.json --env-file .env
```

备份数据库后，显式加 `--apply`：

```sh
PYTHONPATH=backend .venv/bin/python scripts/import_overture.py --snapshot .local-data/overture/beijing.json --env-file .env --apply
```

每次最多各导入 30 条酒店、餐厅。重复执行会从尚未入库、通过去重的候选中继续选择；相同外部 ID 不重复新增。来源初次建立有限期政策和 1,000 条记录许可，之后不自动续期或重置消耗。

验证要求：中国地址、明确城市名匹配、点坐标位于配置范围、已审许可、置信度至少 0.8、类别层级属于酒店或餐厅。坐标来自 WKB 点几何，索引 bbox 仅供范围检查。来源置信度不是用户评分，也不证明商家当前营业。

未知营业状态保留在来源证据中；`active` 表示目录记录有效，不表示“当前营业”。已明确停业的候选不导入。价格、评分、营业时间、图片缺失时保持未知。

同名地点或相近的同类地点（酒店 200 米、餐厅 30 米以内）暂缓入库，保留在原始快照供人工复核。相近不等于同一家，因此不自动合并；此策略可能暂缓不同商家。跨语言、远距离坐标错误等情况仍需人工抽查，不能宣称已完全去重或核验实地营业。

原始快照、备份和本地环境文件位于忽略目录，不提交 GitHub。推荐只将通过来源权限检查的有效地点提供给推荐和行程规划；用户行为仍须来自真实业务，不能用采集记录代替。

## 一条命令遍历城市目录

在项目根目录运行（先安装 `backend/requirements-data.txt` 中的可选依赖）：

```bash
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py
```

默认读取 `.local-data/wikidata-country.json` 中的城市 ID，查询 Wikidata 的城市名称和地球坐标，生成 `.local-data/overture/country/cities.json`。其中 `names` 保存英文与中文名称；文件使用稳定 QID 命名，避免英文重名造成覆盖。该目录是城市候选清单，不是完整行政区划名录。缺失或有歧义的坐标不会猜测，列入 `skipped`。

随后串行采集各城市酒店、餐厅候选，按坐标选择 Overture 数据分区。每个城市中心经纬度各向外 0.05 度，每个相交分区最多 2,000 条；这是中心区域样本，不是全市覆盖，也不保证下载数量等于可入库数量。会重复查询尚未完成的城市；已完成且配置匹配的文件自动跳过。Ctrl+C 停止后重新运行相同命令即可继续。网络恢复后也可重新运行失败项。不要同时启动多份命令，也不要修改已开始任务的城市名单；需要更换名单时用新的 `--output-dir`。

仅生成名单、不下载地点：

```bash
PYTHONPATH=backend .venv/bin/python scripts/collect_overture_batch.py --prepare-only
```

结果保存在 `.local-data/overture/country/`：

- `cities.json`：城市名称、坐标范围、跳过项。
- `Q编号-分区编号.json`：各城市候选地点，含来源和版本。
- `report.json`：任务结束报告，失败或跳过项不为空时退出码为 1。

元数据请求至少间隔 2 秒，失败最多尝试 3 次；地点下载沿用原下载器的请求间隔、流量和超时限制，城市分区之间再间隔 10 秒。全国任务可能持续很久，保持网络连接和电脑唤醒。不会自动启动数据库或写入数据库。

现有 `import_overture.py` 仍只接受原北京、上海、广州预设快照；**不能用它导入这里生成的全国文件**。全国入库还需要扩展城市注册、来源许可范围与导入额度，并保留现有许可及去重检查。不要通过直接写数据库绕过这些校验。原三城市下载、预览和入库命令仍可使用。
