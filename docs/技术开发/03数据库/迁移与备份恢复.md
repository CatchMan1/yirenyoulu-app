# 独立数据库、迁移与恢复

数据库配置按环境独立管理。运行前确认目标实例、库名、账号及权限。

## 选择与边界
采用 PostgreSQL 16（部署时选用经验证的当前16.x安全补丁镜像并锁 digest）。数据库保留外键、检查约束、唯一约束与事务；任务租约与版本冲突由业务层实现并有独立PostgreSQL验证。SQLite仅用于快速约束测试，不能证明 PostgreSQL 并发/锁行为。

开发 `yirenyoulu_dev`，测试 `yirenyoulu_test`，生产 `yirenyoulu_prod`，各自独立实例/凭据/卷。Settings 要求 URL driver 为 `postgresql+psycopg` 且库名匹配 APP_ENV；部署同时使用不同主机、账号权限及网络隔离；配置由运行环境显式注入。

## 开发初始化
需要 Python3.11 与 Docker Compose。已存在独立 `.venv` 时不要重复创建；依赖只装新环境。

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cp .env.example .env
# 编辑 .env，使用密码管理器生成独立 POSTGRES_PASSWORD。
docker compose --env-file .env up -d db
```

将 APP_ENV=development、DATABASE_URL 注入新终端进程（推荐 IDE 环境变量或私有环境管理器），URL指向 localhost:55432 的 yirenyoulu_dev，驱动 postgresql+psycopg，使用独立账号，连接凭据不得出现在共享日志。

```sh
.venv/bin/alembic -c backend/alembic.ini upgrade head
# 可选：导入9个明显标记的虚拟地点；不创建默认账号或用户行为。
PYTHONPATH=backend .venv/bin/python -m app.seed
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
```

初始化只跑 Alembic。应用启动不得调用 create_all 或补列脚本。fixture 导入为独立显式命令，production被拒绝；fixture名字以【测试】开头，价格、评分、营业时间、坐标均未知，不构造真实事实。测试坐标/有效价格边界只存在单测事务。

## 迁移验证
CI 创建空的 PostgreSQL yirenyoulu_test，依次 upgrade→metadata drift check→downgrade→upgrade，并对 PostgreSQL 实际运行唯一性、外键、字段检查、回滚、快照不随目录改变的测试。

本地执行必须设置 APP_ENV=test、DATABASE_URL 指向全新专用空库：
```sh
PYTHONPATH=backend RUN_POSTGRES_TESTS=1 .venv/bin/python -m pytest backend/tests/test_postgres.py -q
PYTHONPATH=backend RUN_POSTGRES_TESTS=1 .venv/bin/python -m pytest backend/tests/test_schema.py -q
```
测试拒绝非test环境及非空库。迁移往返测试会删除其新建表，禁止对有业务数据的库执行。生产迁移先备份、在恢复副本演练，再用专用迁移角色执行。运行角色仅有业务DML，不应有建表/删表权限。`downgrade base` 是破坏性操作，只用于空测试库；生产回滚优先兼容旧版本应用或经审查的前向修复。

## 数据保护与恢复操作说明
使用 PostgreSQL service 配置及权限0600的 passfile 管理连接，下面的 PGSERVICE 名称必须由部署人员指向本项目独立环境。不要把密码写进命令、版本库或日志。备份包含个人数据，必须加密、限制访问、设置保留期且不提交GitHub；生产库备份不可用于开发。

```sh
# 权限最小化；目录应位于本项目以外的受控加密备份位置。
umask 077
PGSERVICE=yirenyoulu_backup pg_dump --format=custom --file="$BACKUP_PATH"
# 先在新的隔离恢复库演练，不覆盖线上库；不使用 --clean。
PGSERVICE=yirenyoulu_restore pg_restore --no-owner --no-acl --exit-on-error "$BACKUP_PATH"
```
恢复后检查 Alembic revision、关键表行数/抽样关联和应用只读健康，再执行恢复环境的业务验收；恢复前阻断外部模型/短信，重放备份之后的账户删除记录后才允许开放。已提供最小删除审计、导出清单和测试环境重放程序；生产仍需将清单独立保存到受控持久存储，并验证访问控制、加密、保留期及恢复流程。

备份频率、RPO/RTO、30天上限与外部法律要求需在正式部署前结合业务确定并演练。

## 模型说明
地点统一 UUID，与来源+外部ID绑定；未知事实保持NULL；图片许可默认不展示。行程地点保存快照，与基础地点外键关联，目录变化不改快照。task→trip 由 trips.generation_job_id 唯一关联，API成功结果通过该关联查询；状态成功与行程保存由同一事务提交，过期租约与旧generation不能保存结果。

## 可执行备份与测试恢复

在已注入独立环境配置的仓库根目录执行；文件路径应使用受控备份目录且必须不存在。生成文件权限0600，失败或中断的文件不能作为有效备份。备份包含私有数据，生产需另有加密存储及独立删除清单保管。

```sh
PYTHONPATH=backend .venv/bin/python -m app.maintenance backup "$BACKUP_PATH"
PYTHONPATH=backend .venv/bin/python -m app.maintenance export-deletions "$DELETION_MANIFEST_PATH"
# 仅对APP_ENV=test、专用yirenyoulu_test有效；会替换该测试库的表。
# 先停止所有API/worker，确认备份及最新的独立删除清单，再恢复。
PYTHONPATH=backend .venv/bin/python -m app.maintenance restore-test "$BACKUP_PATH" --manifest "$DELETION_MANIFEST_PATH"
```

restore-test用pg_restore替换测试库后，在开放服务前事务重放subject UUID清单并使旧推荐模型失效。生产恢复不使用此替换命令，按上文恢复到新实例、重放最新清单并验收后切换。仅有备份内的删除审计无法覆盖备份后发生的注销，最新清单必须独立于被恢复的备份保管。

PostgreSQL HTTP和并发测试需显式设置ITERATION_HTTP_DATABASE_URL；测试会清空专用测试库业务表。备份恢复测试还需PG_DUMP_PATH/PG_RESTORE_PATH。所有测试只在独立环境执行，不使用生产个人数据。
