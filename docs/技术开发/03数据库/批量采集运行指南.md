# 按城市批量获取地点并入库

本程序从 Wikidata 自动发现指定城市的景点、酒店、餐厅，分页读取结构化事实，校验后暂存，并可按固定规则审核入库。只需配置城市 QID，不需要逐个提供地点 ID，也不需要地图 Key、AI 服务或额外付费账号。入口为 `backend/app/bulk_collect.py`。

它使用固定的官方查询与实体接口，不接受任意网址或查询语句。当前支持中国大陆城市，数据覆盖取决于 Wikidata；候选数量、可用事实和实际入库数量均不保证。CC0 适用范围见 [Wikidata 许可说明](https://www.wikidata.org/wiki/Wikidata:Licensing)和[数据访问说明](https://www.wikidata.org/wiki/Wikidata:Data_access)。本程序不获取图片、维基百科正文、高德数据或 OSM 数据。

## 1. 准备本地环境

下面所有命令都在新版仓库根目录执行：

```sh
cd /Users/Admin/Documents/yirenyoulu-app
```

已有 `.venv` 时直接使用；首次安装才执行：

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
```

确认 Docker Desktop 已启动，并且 `.env` 已按[数据库初始化说明](迁移与备份恢复.md)配置。已有 `.env` 时不要用示例覆盖它。需要的配置为：

| 配置 | 本地开发用途 |
|---|---|
| `APP_ENV` | `development` |
| `POSTGRES_PASSWORD` | Docker 开发数据库的独立密码 |
| `DATABASE_URL` | 宿主机 Python 使用的 PostgreSQL 连接；驱动为 `postgresql+psycopg`，默认主机 `127.0.0.1`、端口 `55432`、用户及库名 `yirenyoulu_dev` |
| `JWT_SECRET` | 至少 32 字符的独立随机值；采集不登录用户，但仍需通过项目配置校验 |

`DATABASE_URL` 的密码必须对应目标数据库。密码含 URL 特殊字符时需正确编码，不要把连接串贴到公开日志或聊天中。运行在宿主机的本程序使用 `DATABASE_URL`，而不是容器使用的 `CONTAINER_DATABASE_URL`。

启动数据库并检查状态：

```sh
docker compose --env-file .env up -d db
docker compose --env-file .env ps db
```

这只启动数据库，不需要同时启动 API、规划 worker 或手机 App。数据库已有数据时先按[备份说明](迁移与备份恢复.md#数据保护与恢复操作说明)备份；不要删除 Docker 数据卷或执行降级迁移。

应用最新迁移：

```sh
.venv/bin/python -m dotenv -f .env run --override -- .venv/bin/alembic -c backend/alembic.ini upgrade head
```

迁移创建/更新表结构，不采集地点。采集命令会检查数据库迁移版本，缺少迁移时停止。这里显式加载 `.env`，因为 Alembic 和普通应用入口不会自行读取它；下文采集命令使用自己的 `--env-file`。

本机验证样本目前共 13 条（原 12 条加批量程序验证新增的 1 条），保存在此前的样本实例中，不会自动复制到新建 Docker 库。**本次采集写入哪个库，由 `.env` 的 `DATABASE_URL` 决定。** 若 DBeaver 查看的是另一个实例，即使库名相同，也看不到本次结果。

## 2. 选择城市与采集上限

示例配置为 [`backend/examples/wikidata-bulk.json`](../../../backend/examples/wikidata-bulk.json)。默认包含北京 `Q956`、上海 `Q8686`、杭州 `Q4970`，三类地点每城每类最多发现 100 个候选，即最多 900 个候选；不是承诺入库 900 条。

可以直接使用示例，也可以复制到被 Git 忽略的目录后编辑自己的配置：

```sh
mkdir -p .local-data
cp backend/examples/wikidata-bulk.json .local-data/wikidata-bulk.json
```

| 字段 | 含义 |
|---|---|
| `run_key` | 本次任务的唯一业务键；同键配置必须完全一致。修改城市、上限或审核说明等配置时使用新键，例如 `mainland-pilot-002` |
| `cities` | Wikidata 城市 QID 数组，一次 1～50 个，不可重复；程序读取城市标签并核验国家、城市类型及必要的类别继承证据，不能用猜测的城市编号 |
| `kinds` | `attraction`、`hotel`、`restaurant`，可选择部分类型 |
| `per_city_kind_limit` | 每城每类的候选上限，1～10000；首次运行建议 10～100 |
| `page_size` | 每页候选数，1～20；默认 20 |
| `record_budget` | 该采集来源累计暂存记录的总上限，包含最终被拒绝的暂存行；不是每个任务新增的额度 |
| `request_budget` | 该采集来源累计网络请求总上限；城市核验、发现、地点及行政归属读取、失败重试均消耗请求 |
| `interval_seconds` | 请求操作之间的间隔，1～60 秒；默认 1，不要通过并行启动多个进程规避限速 |
| `review_reference` | 操作员认可的采集范围、来源和自动审核规则说明；请按实际用途填写 |

新增 `run_key` 不清零已用预算。新任务的预算配置调整的是来源累计上限，必须容纳历史已用量；如已用 800 次请求，将总上限改为 1000 只剩 200 次，而不是新增 1000 次。完整重放相同任务不重复创建导入批次。

首次使用会登记独立的 Wikidata CC0 结构化来源、政策及范围许可；已有来源不会自动重置政策。系统政策默认 30 天复核、范围许可默认 7 天；到期或撤回后不会因重新运行而自动恢复，应按[来源管理指南](地点数据导入与来源管理.md)重新核验授权。

## 3. 先采集并暂存

使用仓库提供的示例：

```sh
PYTHONPATH=backend .venv/bin/python -m app.bulk_collect --env-file .env run --config backend/examples/wikidata-bulk.json
```

使用自己的配置时，将 `--config` 替换为 `.local-data/wikidata-bulk.json`。命令先输出 `event: target`，其中的 `environment`、`database`、`host`、`port` 应与准备使用的数据库一致；若发现连接错库，立即按 `Ctrl+C` 停止并检查 `.env`。

随后输出 `run_started`，记下 `run_id`。程序按城市、类型逐页发现，读取地点及行政归属事实，校验后写入采集页和导入暂存表。**不带 `--apply` 会写暂存数据，但不把候选发布到正式 `places` 表。** 完成时任务状态为 `staged`。

运行期间每完成一页会输出 `progress`，最后输出 `report`。访问公共服务的速度和结果数量会变化，等待过程中不必重复启动同一任务。

## 4. 确认规则后正式入库

查看暂存结果，确认配置中的范围与 `review_reference` 符合预期，再执行同一命令加 `--apply`：

```sh
PYTHONPATH=backend .venv/bin/python -m app.bulk_collect --env-file .env run --config backend/examples/wikidata-bulk.json --apply
```

同一 `run_key` 且配置未变时，它使用已暂存的结果继续入库，不重新发现或获取已完成的页面。也可从首次运行起直接带 `--apply`，每页校验后随即入库。

`--apply` 表示操作员授权按固定规则自动审核：类型、城市归属、来源字段、坐标及数据格式校验通过后发布。它**不等于人工逐条核实地点当前营业、价格或完整性**。跨来源同名重复候选仍留待人工处理，不会强行合并；处理方式见[导入指南](地点数据导入与来源管理.md)。

正式入库按来源和外部 ID 更新，已有地点保留内部 UUID。未知坐标、价格、评分、营业时间保持为空，不用 `0` 代替未知；只有来源明确证明免费时，价格才可记为零。采集不生成用户行为。Wikidata 坐标按 WGS84 保存；显示到其他坐标系的地图前按地图适配规范转换。

## 5. 查看报告与数据库

随时查询，不发出新的来源请求：

```sh
PYTHONPATH=backend .venv/bin/python -m app.bulk_collect --env-file .env status --run-key mainland-pilot-001
```

也可使用返回的任务 ID，将 `RUN_ID` 替换为真实值：

```sh
PYTHONPATH=backend .venv/bin/python -m app.bulk_collect --env-file .env status --run-id RUN_ID
```

| 报告字段 | 含义 |
|---|---|
| `status` | `staged` 暂存完成、`completed` 入库流程完成、`running` 执行中、`paused` 手动中断、`failed` 失败；完成不代表所有候选都入库 |
| `discovered` | 已发现候选数 |
| `accepted` | 事实映射校验通过数，尚可能在导入时因重复或规则被隔离 |
| `rejected` | 事实或导入校验拒绝数 |
| `staged` | 当前仍待发布的有效暂存行数 |
| `applied` | 已应用行数，包含新增与更新；不等于数据库总地点数 |
| `inserted`、`updated` | 本任务新增、更新的地点行数 |
| `duplicate`、`skipped` | 待审核的跨来源重复，以及旧观测/已登记别名等跳过行 |
| `remaining_records`、`remaining_requests` | 该来源剩余累计额度 |
| `last_error` | 最近一次失败的稳定错误码，不包含密钥或原始响应 |
| `progress` | 每城每类的断点、候选数和状态；`limited` 表示达到配置上限，不表示该城已采全 |

DBeaver 使用与 `target` 输出相同的连接，展开相应数据库的 `public → Tables`，刷新后查看：

- `collection_runs`、`collection_pages`：任务、配置、发现页、进度及拒绝原因。
- `import_batches`、`import_rows`：暂存、审批、应用结果和重复审核状态。
- `places`、`cities`、`city_aliases`：正式地点及城市；暂存模式下不会新增正式地点。
- `place_external_ids`、`place_field_provenance`：稳定外部 ID、事实来源及观测时间。
- `data_sources`、`source_policies`、`import_permits`：来源政策、复核期限、范围和累计额度。

默认 Docker 连接为 `127.0.0.1:55432`，用户和库名均为 `yirenyoulu_dev`，密码取本地 `.env` 的 `POSTGRES_PASSWORD`。不要根据“库名一样”判断连接一致；还要核对主机和端口。不同实例之间不会自动同步。

## 6. 中断、续跑与更新

按 `Ctrl+C` 正常停止时保存检查点，任务为 `paused`。恢复命令如下；需要直接入库时保留 `--apply`，只暂存则去掉：

```sh
PYTHONPATH=backend .venv/bin/python -m app.bulk_collect --env-file .env resume --run-id RUN_ID --apply
```

`resume` 读取数据库保存的配置，不需要重新提供配置文件。已完成的发现页和已应用的记录不会重建；尚未保存的网络结果可能重新请求并消耗额度。网络失败后先排查原因，再运行同样的恢复命令。

同一任务只允许一个进程执行。异常断电或强制结束后，租约最多需等待约 180 秒；出现 `RUN_BUSY` 时先确认旧进程已停止再恢复。不要手动改数据库游标、租约或记录计数。

已经 `completed` 的同键重跑只返回结果。要获取新一轮事实或提高候选上限，修改配置并使用新 `run_key`；地点通过稳定外部 ID 更新，不依靠名称重复插入。程序不会自动定时采集，首次运行稳定后再由运营安排更新频率。

## 7. 常见问题

| 现象或错误码 | 处理 |
|---|---|
| `SETTINGS_FILE_UNAVAILABLE` / `SETTINGS_INVALID` | 确认在仓库根目录运行、`.env` 存在、驱动及开发库名正确、JWT 随机值长度满足要求 |
| `STORAGE_UNAVAILABLE` | 检查 Docker 数据库状态、连接主机端口与凭据；不要公开完整连接串 |
| `DATABASE_MIGRATION_REQUIRED` | 使用本文迁移命令升级同一个 `.env` 指向的数据库 |
| `CONFIG_INVALID` / `CONFIG_CHANGED` | 检查配置字段及上限；同键不允许改配置，计划变更使用新键 |
| `CITY_COUNTRY_UNVERIFIED` / `CITY_TYPE_UNVERIFIED` / `FACTS_UNVERIFIED` | 城市或地点事实不足，核对官方条目；不要编造归属、类型或坐标来通过校验 |
| `PROVIDER_RETRY_LATER` / `PROVIDER_UNAVAILABLE` | 公共 SPARQL/API 可能超时、限流或返回 429/503；程序每次操作最多尝试 3 次，停止后稍后续跑，不无限重试 |
| `REQUEST_BUDGET_EXHAUSTED` / `PERMIT_EXHAUSTED` | 来源累计额度不足；先看已用量，再按来源管理流程核定新上限，不通过删计数绕过预算 |
| `PERMIT_EXPIRED_REVIEW_REQUIRED` / `PERMIT_REQUIRED` | 范围许可到期或不匹配，重新核验范围；新任务键不会延长有效期 |
| `POLICY_CHANGED` / `SOURCE_POLICY_REVIEW_REQUIRED` / `SOURCE_NOT_AUTHORIZED` | 来源政策已变；停止旧任务，按当前政策重新审核。白名单收缩会清理旧事实及页内载荷，不能沿用旧任务发布 |
| `completed` 但 `inserted=0` | 查看 `updated`、`duplicate`、`skipped` 和 `rejected`；也可能来源没有匹配条目，不能为凑数量放宽事实验证 |
| DBeaver 看不到新增地点 | 刷新表，确认已经 `--apply`，核对 `target` 连接与 `inserted`，区分暂存表和正式表 |

来源到期/撤回后的读取限制与清理属于同一套来源管理机制。需要人工审批、许可续期、重复候选处理或失效清理时，使用[地点数据导入与来源管理](地点数据导入与来源管理.md)中的受控命令，不直接修改业务表。
