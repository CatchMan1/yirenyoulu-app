# 数据字典 · 当前基础与目标约束

2026-10-14，从本仓库SQLAlchemy metadata核对17表字段；此处只描述已有结构，不表示业务权限、轮换、任务与删除流程已实现。SQLAlchemy Record表含UUID字符串主键和created_at/updated_at；place_tags为组合主键。业务用UUID但当前数据库存String(36)，API必须校验UUID格式。

PostgreSQL用于集成和生产，SQLite仅基础单测。金额整数分，时刻UTC，日历日期与分钟按城市时区；首版CNY/Asia/Shanghai默认。坐标成对且CRS明确；未知价格/评分/营业时间null。估算单独存储，不为旧算法保留权重概率字段。

## 关联与不变量

users→auth_sessions/favorites/trips/planning_jobs/chat_sessions/behavior_events；cities→places/trips；places→place_external_ids/place_images/place_tags及收藏和行程地点；trips→trip_items与可选聊天关联。data_sources记录展示与存储许可，图片许可独立，默认不展示。

favorites(user_id,place_id)唯一；external_ids(source_id,external_id)唯一；planning_jobs(user_id,idempotency_key)唯一；trips.generation_job_id唯一；trip_items(trip_id,visit_date,place_id)唯一。消息按(session_id,sequence)及(session_id,client_message_id,role)唯一；行为按(user_id,event_id)唯一。

trip_items保存基础place_id与JSON快照，事实从目录重建，目录更新不能静默覆盖快照；地点被引用时不硬删除，只置inactive。坐标/价格/评分/时段有数据库检查约束；跨行时段冲突、城市一致、日期界限、账户归属、预算及并发幂等仍需服务事务验证。

## 设计差距与后续迁移

当前planning_jobs没有结果删除标记，trip删除会失去generation_job关联；应在后续迁移补result_deleted或等效永久结果墓碑，保持成功任务幂等。auth_sessions只保存当前/上一刷新摘要，若要识别更早轮换令牌重放，需要令牌家族或历史摘要记录，不能声称现有字段已覆盖完整撤销机制。

JSON字段（preferences、snapshot、opening_hours等）需要版本化Pydantic schema，不能仅因JSON可存就接受任意对象。规范见数据传输结构；复杂价格有效期/酒店入住条件、交通估算来源和费用明细尚需细化结构化字段与迁移；现有price_minor只覆盖单一事实价。

未实现：邮箱验证/找回凭据表、注销审计/恢复重放、手动创建幂等、推荐计算缓存/版本元数据、导入批次/检查点与许可到期处理。本轮不修改模型；实施时新增迁移并运行PostgreSQL约束/往返/无漂移检查。不得把设计表格与已运行能力混淆。

审阅新增差距：住宿改为每晚一项、分钟字段均null，非住宿仍为合法分钟区间；需新增迁移放宽现有非空/时段检查并在服务端按真实place.kind校验，每日最多一项住宿。此处当前字段清单仍如实显示现有模型，不代表目标已经迁移。
