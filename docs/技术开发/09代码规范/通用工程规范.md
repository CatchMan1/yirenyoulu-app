# 通用工程规范

适用：React Native iOS、ArkTS/ArkUI鸿蒙及Python FastAPI。本文中的“必须”为合并条件，“建议”为可按业务规模调整的默认。具体产品规则、接口字段与权限以已确认的需求和接口契约为准。

## 1. 架构与职责

中小型新项目默认采用模块化单体和独立客户端；已有项目保留已批准架构，局部应用本规范。页面负责展示与用户意图，请求层负责传输和协议，业务服务负责规则，数据库层负责持久化。平台SDK通过适配器接入；模型、地图、存储供应商实现不直接散落在页面或路由中。

按业务内聚组织代码。新增目录、抽象、依赖必须解决当前可说明的问题；不要求每个函数配接口、工厂或仓储类，不为单次复用拆十几个文件。小模块可同文件组织，复杂业务再拆；不以文件行数作为机械拆分标准。

数据流应能追踪：用户操作→业务服务→HTTP契约→后端规则→事务→响应→页面状态。服务端是已保存数据的真源；客户端缓存不能凭空产生“已创建”事实。长任务由服务端持久化状态驱动，不能依赖页面存活。

## 2. 文件、命名与注释

| 范围 | 约定 |
|---|---|
| TypeScript/TSX | 2空格；组件与类型PascalCase，函数/变量camelCase，常量UPPER_SNAKE_CASE，Hook为useXxx |
| ArkTS/ETS | 2空格；页面XxxPage.ets、组件PascalCase、服务XxxService.ets；字段/方法camelCase |
| Python | 4空格；文件/函数/变量snake_case，类PascalCase，常量UPPER_SNAKE_CASE；导出函数有完整类型 |
| 协议字段 | API边界snake_case，客户端视图模型可camelCase，转换集中在mapper，禁止逐页猜字段 |
| 布尔与单位 | is/has/can等有意义名称；金额/时长在字段名带minor/minutes/ms等单位 |

UTF-8、LF、文件末尾换行。新TS项目默认分号、单引号、尾随逗号及100字符打印宽度；Python默认Ruff的88字符宽度。已有仓库配置优先，ArkTS以SDK支持的格式化器为准，不套用未经验证的Prettier插件。TypeScript使用项目统一格式化规则，Python采用Ruff格式化；同一次改动不夹带全仓格式重排。导入按平台/第三方、内部、相对分组，类型导入独立；避免循环依赖及汇总导出造成隐式初始化。

注释解释业务原因、单位、边界和并发不变量，不逐行翻译代码。公共接口和复杂服务注明输入、输出、失败与副作用。TODO说明缺口及追踪方式，不留下“以后再说”的成功占位实现。对外文案使用资源或集中定义，状态码和错误码不得用中文显示文本代替。

## 3. 类型与数据边界

区分请求DTO、响应DTO、领域对象、数据库模型和视图模型。不直接把ORM全对象或SDK对象发给前端。Pydantic/OpenAPI定义协议，客户端生成或手写类型必须有契约校验；生成器若不支持ArkTS语法，应提供经编译验证的映射，不能硬搬TypeScript产物。

TypeScript类型在运行时被擦除；HTTP、路由参数、本地缓存与第三方回包都需要边界验证。RN可用unknown+收窄或合适的schema库；ArkTS使用对应SDK支持的显式DTO与解析路径，不套用unknown方案。禁止通过any、ESObject或双重断言让错误“消失”。

明确区分缺失、null、空字符串和0。金额整数最小货币单位且校验安全范围；日期不靠设备时区猜测，UTC时刻与目的地日历日期分开。未知价格、时长和评分不能用0填充；来源事实与估算分字段存储、分文案展示。

## 4. HTTP与错误模型

传输层统一base URL、鉴权、取消、超时、协议解码及request_id。本项目JSON业务API统一返回ApiResult<T>：data为已验证DTO，meta为分页元信息或null，requestId映射协议request_id；单条与列表采用同一包装。页面只解一次data，不接触AxiosResponse或data.data。其他项目可沿用其已确定的等效结果类型，但必须明确元信息承载位置，不能混用解包层级。文件、流等响应使用明确专用返回类型；204返回void，不进行JSON解析。

按端点契约处理200/201/202/204，非2xx保持失败。客户端统一错误分类：network、timeout、cancelled、http、contract；HTTP错误保留status、error_code、request_id和经筛选的字段错误。取消是控制流，不显示通用失败弹窗；不能捕获异常后返回空数组冒充成功。

401触发受控会话恢复，403是权限或账户状态问题，404是不存在/不可访问，409要求重新读取或解决冲突，422定位输入，429按Retry-After等待，5xx展示可重试状态。请求ID用于支持排错，不在用户页面展示堆栈或提供方原始报错。

## 5. 写入、重试与并发

服务端提交成功后才返回写入成功。涉及多个对象的业务必须有明确事务边界；重复请求用身份+操作+幂等键+请求摘要辨认，键与输入不符返回冲突。客户端一次操作意图复用同一幂等键，新的意图才创建新键。

读取可以在期限内有限退避重试；写操作仅在服务器明确支持幂等且请求体可重放时重试。网络断线不代表写入未发生，先查回结果。单次操作的总截止时间不能因重试无限延长。

请求取消、页面离开、账户切换与应用回前台必须纳入状态设计。列表/搜索采用取消或递增请求序号，迟到结果不能覆盖新条件。写入使用version或等效并发控制；按钮禁用只改善体验，不能替代服务端约束。

## 6. 认证、隐私与外部SDK

客户端只存必要凭据，敏感持久化使用平台安全存储，普通全局状态和缓存不是密钥容器。启动凭据恢复、刷新、注销用会话代次隔离；任何旧异步结果不能恢复已经退出的账户。跨用户缓存必须隔离并在退出时清理。

存在已确认的刷新协议时，每个客户端进程一次只允许一个刷新请求；等待请求共用结果，刷新不递归经过自身拦截器。先比较请求捕获的session epoch：已变化则丢弃旧响应，不清理当前会话、不使用新账户重放旧请求。仅同一epoch内的token generation变化可考虑合规重放；当前epoch的旋转令牌写入失败或刷新失败时清理该会话；原请求最多重放一次且需满足幂等条件。跨设备会话由服务端独立管理，不能通过客户端“单飞”替代服务器并发校验。

前端环境变量和打包常量视为公开数据；服务端模型密钥、数据库连接、签名私钥不得进入应用包。日志只含事件码、请求ID、状态、脱敏业务标识和耗时，不记录口令、令牌、完整请求/响应、聊天或精确位置。

SDK权限按需请求、允许拒绝；涉及地图时提供地址/列表降级，涉及模型时提供可恢复失败状态。供应商文本和模型输出是待验证数据，不能成为系统指令或SQL。服务域名、导航scheme和回调目标使用允许清单；商业权利和费用独立确认。

## 7. 测试与自动检查

关键正确性需要自动验证：契约、所有权、事务回滚、幂等、并发状态和失败恢复。普通展示组件按风险测试，不追求机械100%覆盖，不测试私有实现细节或只为文档写镜像测试。

| 检查 | 合并要求 |
|---|---|
| 客户端 | 格式/静态检查、类型或ArkTS编译、关键状态与契约测试；原生模块变化补对应构建 |
| 后端 | Ruff、类型检查、pytest；模型/迁移/事务变化补PostgreSQL集成及Alembic无漂移，按风险选择范围 |
| 仓库 | 空白/冲突检查、秘密与禁止文件扫描、依赖锁定及许可证审查 |
| 发布 | Release构建、环境/签名/真实SDK验证、关键业务回归及恢复演练 |

首次引入检查工具时按现有配置建立基线，不能假装脚本已存在。检查未运行应说明原因；模拟器、单测、真实服务、商店验收分别记录，不相互替代。稳定故障修复应增加可重现的关键回归用例。

## 8. 配置、依赖与发布

开发、测试、生产独立实例/凭据/配置；最小权限运行，迁移角色和应用角色分开。仅提交无敏感值的配置样例。一个工程选一种包管理器并提交匹配锁文件；Node、React Native/Expo、SDK及Python版本以验证矩阵锁定，不套用旧教程版本。

结构变更通过版本化迁移，先在隔离副本验证，禁止启动时create_all/补列。部署按版本化制品执行，记录代码、迁移和客户端兼容范围；优先向后兼容的扩展/收缩迁移。备份包含个人数据，应加密并在隔离库恢复演练，恢复后处理注销/删除记录。

提交说明提供具体变化与验证结果；开发文档维护需求、契约、规范和可复现操作说明。
