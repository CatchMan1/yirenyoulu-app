# 鸿蒙前端开发规范 · ArkTS/ArkUI

与[通用工程规范](通用工程规范.md)配合使用。以工程锁定的HarmonyOS SDK/API版本为编译依据；ArkTS不等同于完整TypeScript运行环境。

## 1. 结构与职责

```text
frontend/harmony/entry/src/main/
  ets/
    pages/              # XxxPage.ets，仅页面状态与组合
    components/         # 可复用UI
    services/           # 业务服务与统一HTTP客户端
    models/             # 明确DTO、领域/视图模型与mapper
    common/             # 常量、日志及少量通用工具
    platform/           # 安全存储、地图、定位、导航适配
    entryability/       # UIAbility生命周期入口
  resources/            # 字符串、颜色、尺寸、媒体与路由资源
```

小功能不必创建空子目录；业务专属组件留在相关模块，跨页面才提升为公共组件。服务不得反向依赖pages，领域校验不得藏在build函数中。

## 2. ArkTS类型约束

新增代码定义显式interface/class、数组元素类型、函数入参与返回值。根据锁定SDK使用支持的联合类型/枚举；不直接复制TypeScript的映射类型、条件类型、结构类型技巧或任意对象操作。

禁止any/unknown/ESObject作为业务类型逃生口。TypeScript里“unknown+Record<string,unknown>”的解码示例仅适用于RN，不作为ArkTS范式；不能用object或Record<string,Function>替换后声称已经类型安全。编译器约束以对应SDK实际结果为准。[ArkTS语法适配说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V5/arkts-more-cases-V5)

JSON解析集中在API边界，采用SDK支持的JSON接口与明确DTO映射；有限必要断言仅隔离在适配层，随后逐字段验证必填、空值、枚举与范围。不得在页面直接JSON.parse后断言为最终模型。第三方数据先解码再用于UI，不将任意字典扩散到业务层。

SDK的BusinessError按官方契约处理，不把所有JS错误都盲目转换成BusinessError；统一错误模型保留业务code和request_id，平台错误只保留可公开的错误类别。

## 3. 模块、格式与资源

优先使用锁定SDK中可用的@kit模块，已有@ohos依赖按必要性保留；导入变化先编译，不为了“升级”机械替换所有模块。文件与类型PascalCase，字段/方法camelCase，2空格缩进；资源优先$r，用户文案和主题色不散落为字符串。

页面使用XxxPage命名，组件按职责命名；避免万能CommonUtils、超大ApiService包含所有领域规则。HTTP传输可共享，业务API按模块拆分，在需要时再引入接口注入。

## 4. ArkUI组件与状态

组件明确输入、内部状态和事件输出，父子通信采用当前状态管理版本支持的装饰器。现有组件可保留其状态体系；新模块若采用新体系，在模块边界映射，不在同一组件随意混用两代状态装饰器。

build/Builder只描述UI；不启动请求、存储或定时器。显式loading/empty/error/success状态；新对象/列表更新方式遵循对应装饰器的可观察性规则，不能假设深层原地变更必然刷新UI。

ForEach/LazyForEach使用稳定业务ID。页面路由传入ID和必要参数，不传含敏感凭据或巨大对象的完整状态；详情从业务服务查回。纯展示组件通过参数/回调通信，不直接拿全局token。

## 5. 网络与资源生命周期

统一封装NetworkKit HTTP：base URL、头、连接/读取超时、取消、解码、错误码及request_id。每个创建的HttpRequest明确释放责任，成功和异常都在finally路径destroy；不能仅在成功后释放，也不能释放其他仍在用的共享请求对象。

按端点处理所有约定成功码，204直接结束；非2xx进入标准错误流程。不把201创建或202任务受理当错误，也不把HTTP200中的未知对象自动视为成功。

页面aboutToAppear或相应生命周期触发加载；aboutToDisappear清理定时器、监听和页面持有请求。隐藏与销毁不是同一事件，Tab保留页面/导航返回/App前后台通过状态控制轮询。SDK取消能力不足时用请求序号忽略过期结果，同时释放资源。

搜索、分页及刷新采用条件快照/请求代次，旧响应不能覆盖新条件。写入失败保留已确认数据，服务端版本冲突后提供刷新与重新编辑。

## 6. 认证与安全存储

AppStorage用于UI共享状态，不视为持久安全存储；普通Preferences不保存刷新token。安全凭据通过平台受保护存储/密钥能力适配，具体SDK接口与恢复策略必须实测，不能把“做了加密”当作完整密钥管理。

登录恢复完成前阻止私有请求。启动恢复、刷新、退出用session epoch及串行凭据写入，退出后旧异步结果不得复活会话。响应的session epoch已变化时直接丢弃，禁止注销新会话或跨账户重放。没有刷新协议时仅当前epoch的401转回登录；有刷新协议时一次只刷新一轮；记录发送token代次并处理迟到401，重放限制与幂等要求同通用规范。

账户切换清除用户缓存、路由私有状态和定时任务；凭据恢复失败转回登录，不静默用旧内存值继续请求。日志不输出请求正文、认证头、聊天内容或平台错误原始敏感信息。

## 7. 地图、权限与兼容性

定位按需申请，权限拒绝保留手动城市、地点列表和伴游。SDK初始化和隐私同意顺序按平台要求，地图失败展示地址和可恢复入口。坐标含CRS并验证范围，不用改标签代替转换。

相册、媒体、定位等能力只申请当前功能必要权限；无此功能不先行申请。设备宽度、字体缩放、键盘、安全区域与深浅主题通过资源及布局适配，不将固定像素截图直接作为布局标准。

## 8. 构建、测试与签名

锁定DevEco、SDK、Hvigor/ohpm及依赖版本，使用工程实际wrapper/任务执行编译；配置文件可因明确需求修改，但必须说明兼容影响，不能将旧模板“永不修改配置”作为规范。

代码检查使用实际SDK支持的规则，ArkTS编译必须通过；通用TS检查器不能替代。关键单测/组件测试验证DTO解析、状态变化、失败重试和权限拒绝；HTTP模拟需覆盖201/202/204与异常资源释放。

真机验证平台安全存储、前后台、地图、外部导航及签名；开发预览通过不算正式构建成功。测试/生产包标识、endpoint及签名分开，证书/描述文件/私钥/签名密码不得入库，发布签名由受控渠道注入。
