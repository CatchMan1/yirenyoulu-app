# 双端架构设计

状态：设计 v0.2。当前新仓库只有数据库基础，无可运行新版业务API、无新客户端工程。

## 模块边界

建议目标目录：`frontend/harmony/`（ArkTS/ArkUI）、`frontend/ios/`（React Native/TypeScript）、`backend/`、`docs/`、`scripts/`。这些前端目录是设计，不在本轮建立脚手架。两端分别构建、签名和发布；共用版本化HTTP契约，不共享ArkUI页面源码。

FastAPI模块：auth、catalog、favorites、trips、planning、chat、recommendations。路由处理DTO/身份，服务处理业务和事务，仓储访问SQLAlchemy；不拆成微服务，不为当前规模增加网关/消息总线。DTO实现后导出OpenAPI，双端类型需做契约检查。

API进程接收请求；独立worker领取数据库规划任务。worker和API同一版本发布，使用受限数据库角色；模型提供者不拿数据库凭据。数据库是行程、任务、聊天状态的唯一真源，客户端缓存仅用于显示已确认内容，按用户隔离，注销清除。

## 构建与隔离

新库新账号新卷，不复用旧配置；前端base URL按环境注入。前端不持有模型服务密钥或数据库连接；地图客户端标识按平台限制。后台任务、定时推荐计算、API独立启动但共用受控配置。

迁入鸿蒙源码只采用允许清单，经新契约逐页改造；旧签名、.git、数据集和环境文件不迁入。React Native只复用领域规则/文案/API设计，不直接转换ArkTS代码。主分支与功能分支不是数据库隔离手段。

## 现状与目标差距

[旧代码审查](旧代码审查.md)是读取旧实现所得的阶段证据。已有17表和基础迁移不意味着登录、所有权检查或任务状态机已实现；补齐顺序为DTO/OpenAPI→认证/公共目录/收藏→手动行程→持久化Agent任务→推荐/聊天→两端接入→闭环验收。没有外部凭据的服务分别做模拟验证和真实验证。

并发与失败由服务端判断；先提交事务，再返回成功。对外错误附request_id，内部记录不含敏感请求体。权限、超时与版本冲突规则不由客户端单独保障。
