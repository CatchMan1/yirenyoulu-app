# 前后端联调与兼容规范

## 1. 契约资料与优先级

[OpenAPI](openapi.json)定义JSON形状、字段、参数、状态码及鉴权；[数据传输结构](数据传输结构.md)定义跨字段/权限/事务不变量；[API契约](API契约.md)为开发者入口。三者必须一致，发现冲突先修订，不让客户端自行猜测。当前是开发前设计；业务实现后导出的OpenAPI需经语义比较才能作为实现验收依据。

协议版本位于/api/v1。新增响应字段/错误码可兼容发布，客户端对未知响应字段忽略，对未知错误按HTTP分类；移除/改名/改类型/可空性/枚举语义/鉴权等是破坏变更，必须显式评审并安排客户端兼容窗口或新版本路径，不静默更新。

## 2. 请求、时间与头

生产HTTPS，UTF-8 application/json；有JSON body时Content-Type必填。单请求body上限64KiB，字段长度仍按schema校验。请求不带末尾斜杠，写操作不依赖301/307重定向；uuid路径和参数需编码，重复scalar/未知query参数422。

数组参数重复键：`explicit_tags=id1&explicit_tags=id2`、`status=queued&status=running`；不能用逗号字符串或JSON替代。query布尔仅采用接口明确定义编码，当前没有布尔筛选参数。分页省略用默认值；page超实际结果返回空数组、total保持真实。

响应X-Request-ID为服务器UUID，与JSON一致；204仍含头。客户端提供的请求ID不作为可信日志标识。认证及私有响应Cache-Control:no-store；公共地点是否短缓存由环境策略决定，不能带私有收藏状态污染公共缓存。429带Retry-After整数秒；401带WWW-Authenticate:Bearer。

普通请求客户端连接超时10秒、总等待30秒；发送聊天总等待60秒，服务端提供方处理截止45秒。规划创建仍是短请求，任务独立120秒，不让一个HTTP请求等待整个规划。任务轮询初始2秒逐步退避到5秒，离开/后台暂停，恢复GET任务列表；deadline后允许5秒状态收敛，若仍非终态提示服务异常而不在客户端伪造成功或失败。

## 3. 认证与跨账户响应

注册201 User后明确登录；登录200 LoginResult{tokens,user}，访问令牌15分钟，刷新最长30天且轮换不延长会话绝对期限。每次请求服务器检查账户和会话撤销。注销/改密/重置后会话全部撤销。

只有401 SESSION_INVALID参与访问令牌刷新；INVALID_CREDENTIALS、CURRENT_PASSWORD_INVALID不触发刷新，403也不刷新。收到任何结果先比较发送时session epoch；已切换账户则丢弃，不注销新账户或跨账户重放。相同epoch内单个refresh Promise处理并发401；迟到401先比较token generation。

POST refresh不自动重试。首版旧刷新令牌重放撤销会话，若旋转成功而响应丢失，清理本地并重新登录，不能无限重放旧令牌；这一限制是首版明确的网络恢复行为。认证响应只在同一epoch内串行写入安全存储后生效。退出先使本地epoch失效并清理私有数据，后台尽力撤销服务器会话；网络失败不能恢复本地登录。logout本身使用有效Bearer，过期时可无法完成服务端撤销，直到到期/后续账户管理撤销，界面不能宣称已撤销所有设备。

邮箱验证与找回通过单次凭据；服务商和回链未配置时不启用成功路径，不接受短信或调试码代替真实邮箱验证。开发模拟必须标mock，生产拒绝模拟。

## 4. 客户端服务接口

鸿蒙和RN对同一operationId使用同一字段/结果语义，分别实现解码器。业务JSON方法统一返回ApiResult<T>={data,meta,requestId}，meta对应null/PageMeta/CursorMeta；204返回void。不得混用AxiosResponse、data.data与裸业务对象。request_id从wire映射requestId，分页data始终数组。

响应字段稳定必返（包括null），runtime校验在边界完成。RN使用unknown收窄/schema验证；ArkTS显式DTO并用锁定SDK支持的解析手段，禁止ESObject掩盖差异。实例类型定义或OpenAPI生成不替代运行时校验；对新增可忽略字段保留前向兼容。

统一ApiError包含kind(network/timeout/cancelled/http/contract)、httpStatus或null、code或null、message、details和requestId或null。取消不弹失败提示，422显示字段错误，409保存用户输入再刷新，503/504不返回假数据。只在有服务器响应时期待requestId；网关无法提供统一体的HTML/空响应作为transport/contract失败处理。

## 5. 写入与重试

| 操作 | 重试规则 |
|---|---|
| 公共GET/本人GET | 总期限内最多2次退避重试；不重试401/403/422 |
| PUT/DELETE收藏 | 同账户可以重放，仍处理地点失效/会话失效 |
| POST手动行程/规划任务 | 原Idempotency-Key与原语义输入，查回结果；不能因断网换键 |
| PATCH/DELETE行程或地点 | 不盲目自动重放；先GET确认版本和目标结果，409要求重新编辑 |
| POST会话创建 | 无幂等保证，不自动重放；成功响应丢失时先查会话列表 |
| POST聊天消息 | 仅最后一轮失败可同message_id/原内容重试；旧轮MESSAGE_RETRY_EXPIRED，GET恢复不自动另起同文消息 |
| POST行为事件 | 同event_id/原内容重试，先去重再校验首次时间窗口；duplicate不增加权重 |
| 注册/登录/refresh/改密/注销/找回确认 | 不自动重试，按身份和结果恢复规则处理 |

本次明确目的地/日期/预算/硬偏好优先。提交表单前验证基础输入，但所有跨字段和权限仍由后端保证。HTTP失败时保存草稿，不改变已确认对象。测试schema校验只能证明形状，不能证明事务、权限或模型事实。

## 6. 联调顺序与验收

先用[协议样例](contract-examples.json)验证成功、空列表、204、409、422、任务202和无坐标降级。样例只供隔离测试，不冒充真实地点或业务运行结果。结构检查之外，联调覆盖以下场景：

1. 登注册、refresh轮换、无效/撤销token、迟到401与账户切换；错误密码不触发刷新。
2. 同条件列表分页、重复标签编码、未知价格与单位、空/失效详情；两端相同字段含义。
3. 两用户资源越权、子资源归属、乐观版本竞争、提交失败无成功提示。
4. 同键同输入/不同输入/删除结果/过期墓碑；任务重启、旧worker、取消及超时竞争。
5. 住宿空分钟/连续两晚/每日一酒店、快照变更与未知预算、失效项目仍能编辑其他内容。
6. 多轮上下文、失败消息槽位复用、序号游标、会话删除与在途回复竞争。
7. 地图/模型/邮件mock与真实验证分列；断网、后台恢复、安全存储失败。

每条记录端、环境、提交、输入、预期、实际与证据。没有实际业务服务时不标联调通过；后端通过不替代客户端编译/真机，模型模拟不替代真实免费服务验证。

## 7. 实现与schema检查

后端Create/Update/Read DTO按schema编写，写入extra=forbid并避免不期望的类型强转；输出通过公开模型筛选。GET/DELETE查询参数明确拒绝未知或重复scalar。字段验证错误需要转换为统一422格式，不能使用框架默认回显敏感输入。

实施后导出OpenAPI并检查：operationId唯一、路径和参数匹配、公开端点无隐式鉴权、私有端点有Bearer、204无content、所有错误为统一体、所有$ref存在、示例通过JSON Schema与格式校验。数据库跨行约束/状态竞争再由PostgreSQL和双端故障用例验证。
