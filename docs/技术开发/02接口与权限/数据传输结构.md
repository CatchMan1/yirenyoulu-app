# 数据传输结构与接口补充

设计 v0.2；与[API契约](API契约.md)一起使用。Pydantic DTO/OpenAPI尚未实现，本文件不宣称机器契约已验收。字段使用snake_case；UUID为字符串；可选缺省与显式null须按下面规则区分，写请求拒绝未知字段。

## 公共类型

| 类型 | 字段及规则 |
|---|---|
| Preferences | tags: UUID数组≤20，pace: relaxed/normal/fast（默认normal）；硬约束另用explicit_tags，软标签只参与排序 |
| Coordinates | longitude数值[-180,180]、latitude[-90,90]、crs: GCJ-02/WGS84/BD09；三者齐全或整个对象null |
| PriceFact | amount_minor≥0整数、currency=CNY、unit=entry/night/person、observed_at: UTC或null；整个对象null表示未知 |
| Estimate | amount_minor≥0整数或null、reason字符串、source字符串或null；始终独立于PriceFact，不是来源报价 |
| Provenance | source_name、source_url或null、checked_at或null；只输出可公开来源URL，无私密访问参数 |
| User | id、username、email、email_verified、nickname≤50、signature≤200、preferences；不输出密码哈希/内部角色 |
| Place | id、kind、name、city:{id,name,timezone}、category或null、tags、address或null、coordinates或null、price或null、estimate或null、status、provenance、is_test |
| PlaceDetail | Place+description或null、opening_hours或null、rating:{value,scale}或null、images:[{url,source_name}]、hotel_stars或null、cuisine或null；images只含允许展示项 |
| TripSummary | id、title≤200、city_id、start_date、end_date、budget_minor或null、version≥1、created_at、updated_at |
| Trip | TripSummary+preferences、items、cost_summary、warnings；按visit_date/start_minute/id稳定排序 |
| TripItem | id、place_id、date、start_minute或null、end_minute或null、note≤1000、snapshot、current_status、estimated_cost_minor或null、estimate_reason或null |
| Snapshot | schema_version=1、name、kind、address、coordinates、price、provenance、captured_at；保存时从目录复制，不能接受客户端注入事实 |
| CostSummary | known_cost_minor、estimated_cost_minor或null、unknown_item_count、currency、complete布尔；complete=false时不能称总额满足预算 |
| Job | id、status、trip_id或null、result_deleted布尔、error_code或null、warnings数组、created_at、updated_at、deadline、provider_mode: disabled/mock/real |
| Session | id、title≤100、trip_id或null、created_at、updated_at |
| Message | id、message_id、sequence、role:user/assistant、content、status、error_code或null、created_at |
| MessageTurn | user_message、assistant_message、provider_mode |

所有列表page从1开始，page_size默认20上限50，稳定排序加id作为平局键，total与过滤一致。聊天采用before_sequence排他游标，limit默认20上限50，取较旧消息后按sequence升序返回；meta含next_before_sequence或null，不伪造page/total。

## 写入与一致性

PATCH缺失字段表示不修改；只有budget_minor、可选关联等声明允许清空的字段接受null。昵称/签名可为空字符串；日期必须提供明确值而非null。Trip日期字段统一start_date/end_date，TripItem对外date映射数据库visit_date；不使用dates模糊对象。所有private资源user_id由服务端会话决定。

POST/PATCH/DELETE行程地点和PATCH行程以请求JSON的version为比较版本；DELETE行程及地点用查询参数version（无JSON请求体）。服务端锁行程并比较version，校验整个行程后写入并增长版本；失配409。删除账户采用JSON current_password，客户端和反向代理契约测试覆盖DELETE请求体；日志禁止记录。

同一手动创建意图的POST /trips使用Idempotency-Key（1..100可打印ASCII字符），与用户、路由和规范化请求摘要绑定；保留至少24小时，重放返回同一行程，改输入409。该幂等记录需要后续迁移，当前模型尚无该表。地点新增以place/date唯一约束及version防止重复；断网后先GET查回，不盲目重复写。

Job的succeeded表示曾成功提交行程；若用户随后删除行程，GET返回trip_id=null/result_deleted=true，不回建。规划请求相同键重放同任务，即使行程已删除也不重新保存；需要新生成意图使用新键。至少保留幂等记录至账户注销；具体清理不得导致旧键重复生成。

## 可判定的请求示例（虚拟结构，不是现有真实数据）

```json
{
  "city_id": "00000000-0000-4000-8000-000000000001",
  "start_date": "2027-01-01",
  "end_date": "2027-01-02",
  "budget_minor": null,
  "preferences": {"tags": [], "pace": "relaxed"},
  "explicit_tags": [],
  "request_text": "慢节奏，优先已核实的信息"
}
```

以上用于POST /planning-jobs并附Idempotency-Key。测试需实际创建对应虚拟城市，不能假定此UUID已经存在。城市无有效候选则任务failed/NO_CANDIDATES。成功创建任务返回202；客户端仅在查询得到succeeded和可读trip后提示创建成功。

错误示例：`{"error":{"code":"VERSION_CONFLICT","message":"行程已更新，请刷新后重试","details":[]},"request_id":"请求标识"}`。request_id实际由服务端生成UUID。统一错误码至少覆盖INVALID_INPUT、INVALID_CREDENTIALS、SESSION_INVALID、ACCOUNT_CONFLICT、NOT_FOUND、VERSION_CONFLICT、IDEMPOTENCY_CONFLICT、RATE_LIMITED及智能服务文档任务错误。

## 尚需实现的结构

邮件验证/密码找回、删除审计、手动创建幂等、推荐计算版本缓存、交通估算来源、数据导入批次检查点均有设计需求但当前17表不完整覆盖；必须用新版本迁移补齐，不修改已发布初始迁移。OpenAPI生成时逐一落实这些DTO，并用两端fixture比较；不自动把ORM对象全字段暴露给客户端。

## 住宿和历史快照补充

住宿由snapshot.kind=hotel识别；一项一晚，date为入住日、次日退房，分钟字段必须均null；非住宿分钟字段必须齐全且合法。服务端从place重建kind，不信任客户端声明。每日最多一项住宿；住宿不参与白天时段互斥，所有退房日必须≤trip.end_date。现有分钟列不可空，需后续迁移；两端将住宿显示为独立的当晚卡片。

编辑已有项目只改时间/备注时不刷新快照；替换place_id才检查当前有效性并重建快照。未替换的失效地点允许保留并警告；纯标题/备注修改及删除不因预算阻塞。日期边界/预算重新计算具体规则见Agent与推荐的审阅裁决。
