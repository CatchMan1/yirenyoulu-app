# 数据传输结构与业务不变量

字段机器定义见[OpenAPI](openapi.json)，路由见[API契约](API契约.md)。所有示例使用虚拟资料；当前规范是开发依据，字段已定义不代表数据库或API已经实现。

## 1. DTO与空值

| 类型族 | 含义与约束 |
|---|---|
| RegisterRequest / LoginRequest / TokenPair / User | 注册不直接登录；LoginResult包含tokens与user；刷新只返回TokenPair |
| City / NamedEntry / Preferences | 城市有时区；分类/标签均为id/code/name；偏好软标签≤20，pace默认normal |
| Place / PlaceDetail | 三类统一UUID；详情补介绍、图片、营业时间、评分及类型字段；只公开有权展示的资料 |
| Coordinates / PriceFact / Estimate | 坐标三字段齐全或整体null；真实价有币种/单位；估算与来源事实分离 |
| Snapshot / TripItem / Trip | 快照schema_version=1；地点外键与快照共存；Trip包含完整items、费用和警告 |
| Job | 六态、deadline、trip_id、result_deleted、error_code及provider_mode |
| ChatSession / Message / MessageTurn | 本人会话；message_id标识客户端一轮，id标识数据库单条消息，sequence标识会话顺序 |
| PageMeta / CursorMeta | 页码列表与消息游标元信息互斥，不能通过丢弃meta统一成裸数组 |

所有响应schema列出的字段都返回，缺失事实用null；数组无结果为[]。响应可新增字段，客户端忽略不认识的响应字段；写请求及已知嵌套对象拒绝未知字段。不能把响应extra字段原样送回写接口。

PATCH省略表示不改；null只用于schema明确可空的字段。nickname/signature可设空字符串；title不能全空白；preferences提供时整体替换，缺省tags=[]、pace=normal。Create缺省budget_minor=null、preferences={tags:[],pace:normal}；其他默认值由schema与端点说明给出。

用户名标准化小写，邮箱去两侧空白并小写。标题/昵称/搜索词去两侧空白，保留正文内部空白；密码、refresh_token、恢复凭据及message content不做静默改写；纯空白消息拒绝422。消息摘要以原内容UTF-8计算。

所有整数输入必须为JSON整数，不接受字符串、bool或浮点数隐式转型；UUID格式、日期、UTC Z时间严格验证。单项金额与预算为CNY整数分，0..100000000；费用汇总使用0..9007199254740991的安全整数范围，不沿用单项上限；未知不是0。首版只有Asia/Shanghai城市，不将海外时区/币种塞入现有字段假装支持。汇总在服务端使用精确整数计算，若持久化汇总需64位整数，不存入单项32位金额列。

列表筛选中格式正确但不存在的城市/分类/标签返回空结果，不回退其他城市或忽略硬条件；创建行程/任务的city_id必须有效，否则404 NOT_FOUND。写入偏好或硬标签时标签必须存在，否则422 INVALID_INPUT（对应字段INVALID_COMBINATION）。

## 2. 地点事实与导航

coordinates仅含longitude/latitude/crs，整体未知为null；范围合规不代表地点真实，必须保留来源并核验城市。评分value必须≤scale，量表不可混比。hotel_stars仅hotel可非空，cuisine仅restaurant可非空；星级或评分未知不推断。

opening_hours整体null表示没有资料；unparsed仅显示raw_text，weekly=[]；parsed要求weekly非空，日段opens<closes，跨午夜拆段。节假日和临时停业未知时不承诺正在营业。图片url必须有独立展示许可；首版不暴露来源私密访问参数。

首版Place.estimate固定null，真实价只返回PriceFact；规划所需估算存于TripItem，不作为公共地点报价。导航mode默认walking；provider省略则用后端部署已配置默认，客户端配置可通过调用参数明确amap/google。服务未启用或CRS不支持，200 unavailable带reason；available必须有已知坐标和受限url、reason=null。链接只接受审核过的供应商域名/scheme；不返回带服务端API密钥的链接。

## 3. 行程与住宿

行程单城市，起止日期包含首尾且1..14天，最多100项。city_id创建后不可修改；改变目的地创建新行程。日期以目的地日历为准，不按设备UTC偏移换日。整行程数据读取按date、非住宿start_minute、id稳定排序；住宿排在当日非住宿之后。

非住宿项目分钟必须都为整数，0≤start<end≤1440，按同日时间段互斥；零长度、只有一个分钟或跨午夜拒绝。酒店项目一项代表一晚，date为入住夜，次日退房；start_minute/end_minute必须均null。不占用白天游览时段，每日最多一项住宿；退房日≤trip.end_date，单日行程不安排住宿。

同日同地点不能重复，跨日同酒店可重复且按夜计费。增加/替换时后端从目录重建kind、快照、价格和坐标，不接收客户端快照/事实/任意地点。若替换改变kind，必须同请求提供该类型合法的分钟对；省略时间仅在原类型仍兼容时继承。

新增/替换要求地点active、同城；未替换的失效地点可保留并警告。修改时间/备注不刷新快照，改place_id才重建。标题/备注修改和删除不会因失效地点或历史预算阻塞；日期变更不能使保留项目或退房日越界，先调整地点再缩短日期。

所有编辑检查归属、父子关系及version；每次有效修改将Trip.version增加1，失败不增长。提交前相同行程锁内复用日期/时间/重复/预算规则。POST/PATCH成功返回完整Trip及新版本；客户端不自行推算版本。

## 4. 费用与预算

known_cost_minor只统计有同单位依据的事实价，住宿每夜、餐厅每次每人、景点每次入园，首版人数固定1。一个有效0价格必须有来源依据。estimated_cost_minor是已知成本加可得未知项估算的合计，不与known_cost再叠加；只要仍有未估算项目或未知交通费用则该合计可为null。unknown_item_count统计缺事实价格的项目（即使有估算仍计入），不把估算算作已核实事实。

complete=true仅表示计划费用范围内没有未知事实项/必要交通费用，不表示可预订报价或未列入项目已覆盖。空手动行程known=0、estimated=null、unknown=0、complete=true。费用范围包括计划地点及已知必要交通费用，机票/出发地到目的地等未列入费用在页面说明不包含。

新增/替换及修改预算时计算保留快照+新项目事实：已知成本下界>预算拒绝BUDGET_EXCEEDED；仅估算超预算返回ESTIMATE_OVER_BUDGET警告，未知返回COST_INCOMPLETE，不宣称满足预算。已知交通时间要计入相邻间隔校验，未知交通时间给警告而非0。

## 5. 任务与幂等

POST /planning-jobs只做身份、结构、可识别的输入冲突与依赖检查；数据库queued持久化后返回202。未配置提供方503不创建任务，但同键已存在时先返回既有任务。后续Agent发现文本与表单矛盾或事实不足，任务failed/PLAN_INVALID，不覆盖明确输入。无有效候选failed/NO_CANDIDATES。

queued→running→succeeded/failed/timed_out/cancelled；终态不可反转。deadline为创建时刻+120秒（含排队），最多8次受控工具调用、最多2次有限重试。外部工具失败/模型输出必须校验；模型没有任意SQL权限。

worker持久租约和generation；取消、超时和最终保存竞争同一任务锁。提交同时写Trip/Items/服务端行为及succeeded；任一失败全部回滚。running或queued不得带trip_id；succeeded有可读trip_id且result_deleted=false，用户删除后变为trip_id=null/result_deleted=true；其他终态trip_id=null，failed/timed_out必须有error_code。

创建幂等键限定ASCII字母数字及._:-，建议UUID；作用域=user+HTTP方法+路径模板。请求先校验/标准化，再对含默认值的语义JSON做摘要；对象键排序，集合型标签排序，request_text保留原文。身份/操作相同、键相同、摘要不同409 IDEMPOTENCY_CONFLICT；重复相同输入返回原201/202结果，响应request_id可不同。

手动行程保存响应可重放24小时，此后保留键摘要墓碑并返回409 IDEMPOTENCY_KEY_EXPIRED，不因记录过期重建；原行程已删除返回410 RESOURCE_DELETED。任务保留幂等记录至账户注销；删除生成行程不删除任务幂等结果。请求事务回滚不产生成功记录，客户端断网使用原键查回，不能换键盲目重建。

## 6. 消息及上下文

发送使用客户端message_id(UUID)，同会话/同键/同内容成功重放201 MessageTurn；同键异内容409 IDEMPOTENCY_CONFLICT。单会话一轮pending/running，其他轮409 SESSION_BUSY；同轮处理中409 MESSAGE_IN_PROGRESS，前端GET消息恢复，不再追加。

用户与assistant各占固定序号，同一message_id关联两条不同id消息。用户content≤4000，assistant≤8000；失败assistant.content为空字符串并有error_code，成功assistant.content非空且error_code=null。provider超时返回504/失败503，同时保留失败槽位；只有最后一轮失败可原位重试。若已存在序号更晚的用户轮次（无论结果），旧轮重试返回409 MESSAGE_RETRY_EXPIRED，页面移除其原位重试入口；用户可明确创建新一轮提问。重试判断与新轮创建竞争同一会话锁，不将旧回复插回已完成的后续对话。允许的重试复用message_id/消息序号，租约防永久处理中。提交前检查会话未删除、本人仍有效，不能复活已删除会话。

GET messages不带游标返回最近limit条，按sequence升序展示；before_sequence排他取更早记录，再升序返回。若还有更早记录，next_before_sequence为本批最小sequence，否则null；空列表next=null/has_more=false。包含pending/running/failed槽位供恢复，但只有成功消息进入模型上下文。

模型仅使用当前用户sequence之前、user和assistant均成功的完整轮次（最多20条消息），加当前用户消息及可读本人行程摘要；不包含未来序号、失败轮次或孤立的已接收用户消息。序列化输入最多16000字符，并进一步限制在实际模型token预算内，从最旧整条消息裁剪。未绑定/已删除行程不提供其他用户背景；首版无自动聊天改行程动作。模型地点事实来自受控工具，缺失明确说明。

## 7. 行为、推荐与服务端映射

客户端只上报view，event_id去重且绑定place/type/occurred_at；异内容409，不重复积累信号。完成身份/字段检查后先查已有event_id：同摘要直接duplicate、异摘要409；仅首次接收的occurred_at要求与接收时刻最大偏差5分钟。延迟超过窗口且未曾成功接收的事件422，客户端丢弃，不伪造新时间补报；服务端接收时间作为计量依据。fixture环境事件origin=test由服务端决定，客户端不能伪造real；收藏/取消/加入行程事件与成功事务同时产生。

推荐先应用city/kind/explicit_tags/价格单位硬条件，再用历史偏好排序。协同数据不足返回fallback_preferences或fallback_catalog，不宣称已验证个性化；空候选返回items=[]而非错误。algorithm_version始终返回可追踪版本。

对外date映射trip_items.visit_date，coordinates.crs映射coordinate_system，price.amount_minor映射price_minor，message_id映射client_message_id。Job.trip_id通过结果关系查回，删除墓碑需补结构；HTTP响应不得直接序列化ORM内部字段。会话恢复、结果删除、住宿空分钟、费用与交通来源等缺口使用新迁移补齐，不改已应用迁移。
