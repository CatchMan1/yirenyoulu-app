## 目标和边界
保留 ArkTS/ArkUI 与 FastAPI。以注册登录、资料与账户管理、三类地点浏览搜索筛选详情、收藏、行程与每日地点编辑、地图导航、AI 伴游与历史会话形成闭环。日常推荐为真实行为协同过滤与明确偏好/基础排序兜底；行程生成改为受控工具 Agent，本次明确要求优先。禁止继续依赖旧 TOPSIS、熵权或概率字段。订单、支付、预订、社交和运营后台不在当前范围。

用户已决定：用户名/邮箱与密码先上线，短信后续；地图使用高德 API；AI 只使用免费接口。免费额度、商业许可及可用模型仍须核实，禁止自动转为付费或开通服务。未配置真实服务时返回可识别的 disabled/mock 状态；模拟数据和模拟回复不能冒充真实服务。

## 架构与环境（实施者决定）
单仓库 `frontend/`、`backend/`、`docs/`、`scripts/`、`.github/workflows/`。后端采用按业务划分的模块化单体：auth、catalog、favorites、trips、planning、chat、recommendations。HTTP、业务规则、ORM 边界明确，无微服务或无业务需要的通用框架。API 和持久化任务 worker 可分别运行，使用同一版本的领域代码。

PostgreSQL 作为开发集成、CI 集成、生产的一致数据库，SQLAlchemy 2 + Alembic 管理结构。理由：外键/检查约束、事务、行锁与任务并发领取可复用同一数据库，当前无需引入 Redis 和额外消息系统。SQLite 只可用于明确标记的快速单测，不能代替 PostgreSQL 事务/锁/迁移验收。Python 3.11 独立 `.venv`，可复用现有 py311_env 的解释器创建，不安装到旧项目环境。开发/测试/生产使用独立凭据、库、卷、配置；测试显式拒绝生产库名，生产拒绝 fixture 来源。生产数据库不对公网开放，运行账号不拥有 DDL，迁移账号分开。

ArkTS 保留现有页面布局与组件，逐页接入 `/api/v1`，不保留旧 HTTP 契约的隐式兼容层。API 21 为现有构建基线，SDK 是否符合上架要求在发布准备阶段核实。缺少 DevEco/SDK 时只能报告静态检查，不能声称完成 ArkTS 编译或真机联调。

## 身份与权限
账户：用户名、邮箱（标准化唯一）、Argon2id 密码哈希、状态、资料、偏好、创建/更新时间。访问令牌短期有效（15 分钟），服务端维护会话和可撤销的刷新令牌哈希（30 天上限），刷新轮换；登出、改密、注销撤销相应会话，重用旧 refresh token 撤销整个会话。JWT 固定算法、issuer、audience、sub=user UUID、session UUID、过期与签发时间均校验。

匿名仅可读有效公共地点；用户仅能读写自己的收藏、行程、任务、行为、会话和消息。请求不得指定 user_id 代替身份。跨用户资源统一 404；未登录/过期统一 401；禁用账户 403。改密和注销需最近认证或当前密码。邮箱未验证不宣称已验证，邮件找回在接入邮件服务前禁用；上线前必须解决可验证邮箱/恢复渠道，属于外部服务决策。注册/登录/刷新限制频率，日志不含口令、token、验证码、请求体、模型完整提示词或数据库 URL。

## 数据模型
所有业务主键用 UUID，时间用带时区 UTC，行程日历日期用目的地时区（首版 Asia/Shanghai），金额为 CNY 整数分，未知为 null。事实字段与估算分开；零价格必须有明确依据。

- users、auth_sessions：身份与撤销/轮换状态。
- cities、categories、tags、place_tags：规范化目的地、类别和标签。
- places：统一三类地点标识，kind=attraction/hotel/restaurant；名称、描述、城市、分类、地址、经纬度/坐标系、状态、来源及更新时间；酒店星级/餐厅菜系等类型字段有验证约束，评分记录原始量表，不将不同来源分值直接比较。
- data_sources、place_external_ids：source+external_id 唯一；来源 URL、许可/商用与缓存说明、采集/核验时间；数据来源可为 fixture，必须有明确标记；图片独立记录来源与使用许可，未知许可不对外展示。
- place_prices/opening_hours 或经验证的结构化字段：真实价格及币种/计价单位/生效期、营业时间原文与结构化内容；估算费用单独存储 reason/confidence，不覆盖真实价格。
- favorites：(user_id, place_id) 唯一；首版收藏地点，不引入他人行程收藏。
- trips、trip_items：用户归属、标题、目的地、日期、预算、偏好、版本号；地点基础外键+保存时快照（名字、坐标系、地址、来源、核验时间、价格事实及估算），后续目录更新不静默改写快照。已失效地点可在历史行程查看并警示，不可新加入；不硬删除仍被引用的地点。
- planning_jobs：用户、幂等键、请求摘要、状态、deadline、lease/attempt、结果 trip_id、错误码和时间；user+idempotency_key 唯一，trip 对 job 唯一。
- chat_sessions、chat_messages：归属、标题、可选本人行程、消息序号/角色/状态；user 消息、模型回复与失败状态可追踪，模型只接收本人同会话的有界历史。
- behavior_events：本人行为 view/favorite/unfavorite/trip_add，event_id 去重、place_id、时间、origin=real/test；不采集原始敏感搜索词或精确轨迹。生产推荐排除 test 与已注销用户。

坐标：保存来源原坐标和 crs；高德使用 GCJ-02，禁止未标注地混用 WGS84/BD09。地图适配器只接受已知 CRS，确需转换由受控转换服务处理并记录来源；绝不把坐标系标签改写当成转换。经纬度必须同时存在或都为空，验证范围；空坐标降级为地址文本并禁用导航。

## 接口及错误
具体契约见 `docs/api-contract.md`。统一响应 data/meta/request_id，错误 error.code/message/details/request_id；不以 HTTP 200 承载业务失败。分页 page>=1、page_size 1..50。写操作提交事务成功后才能返回成功。并发编辑使用 version 乐观锁，冲突 409；输入非法 422，缺失 404，限流 429，第三方不可用 503/超时 504，内部错误 500 且仅给 request_id。

## 行程 Agent 与任务
POST 创建任务返回 202 和 job_id，前端轮询受限间隔与截止时间。状态 queued→running→succeeded/failed/timed_out/cancelled。领取任务用 PostgreSQL 锁与 lease，重启后回收过期 lease；有限重试，deadline 到期禁止继续保存。禁止仅靠 FastAPI BackgroundTasks 或进程内 dict 保证任务可靠性。

Agent 只能调用 allowlist：search_places(city_id, kind, tags, limit<=50)、get_place(id)、get_travel_estimate(ids, mode)。工具有 Pydantic 输入/输出 schema，参数化 ORM，限定目的地与有效状态，无 SQL/网络任意请求工具；工具事实与用户指令分层，不把地点描述当系统指令。每任务最多 8 次工具调用、单调用超时、总耗时 120 秒、输出大小上限。免费模型未配置时开发可注入确定性的 FakePlanner，生产拒绝模拟 provider。

模型仅返回 place_id、日期、起止分钟、估算及说明；名字坐标从数据库重建。程序在保存前校验地点存在/有效/城市一致、日期范围、重叠、每天重复地点、预算已知成本下界及估算。跨天住宿可重复，同日重复默认拒绝；未知成本保留 null 并提示预算不完整，不声称满足预算。修改地点和行程日期时复用同一验证器。最终持久化行程、items 与 job succeeded 在单事务，任务成功意味着可从数据库读取完整行程；无缓存行程详情入口。

## 推荐与 AI 伴游
行为链路先做事件去重和用户归属，再实现稀疏 item-item 协同过滤（时间窗口、行为权重、相似度、候选过滤有版本参数）。最低有效用户/交互阈值未满足时返回 reason=fallback_preferences 或 fallback_catalog。合成测试只能证明计算和调用链路，不能证明个性化效果。用户本次目的地、预算、偏好是硬约束，历史推荐不得覆盖。

AI 伴游读取有界历史（最近 20 条/输入长度预算），模型失败返回真实状态，重试以客户端 message_id 幂等，禁止重复追加。聊天涉及地点事实通过目录工具，未知明确告知，禁止旧提示词中的虚构亲历或无条件赞同。免费额度耗尽返回 provider_unavailable，不降级为付费模型。

## UI 验收
所有页面明确 loading、empty、error+retry；成功提示以持久化确认和任务状态为准。401 清理会话并引导登录，重试写操作保留幂等键，离开页面取消轮询/释放 HTTP 资源。地点详情未知价格/营业时间显示“暂无资料”；测试来源常驻明显标识。地图失败保留行程和地址文本，导航无坐标/服务不可用时解释原因。

## 设计审阅后的补充裁决
独立 builder check 于 2026-10-13 指出以下问题，均为已授权范围内的常规技术决定：
- 推荐单地点预算使用 price_max_minor + price_unit；未知价格排除在硬上限过滤结果之外；它不代表行程总预算。明确标签采用 all 匹配，软偏好另用 preferred_tags。
- 每次任务领取增加 lease_generation；最终事务锁 job，验证 generation、running 状态、deadline 和用户有效性。取消和提交竞争同一行锁，先完成的终态获胜；旧 worker 无权写入。过期 worker 与新 worker 的并发场景必须 PostgreSQL 验证。
- 聊天 message_id 唯一且绑定内容摘要；同键不同内容409；成功重放现有结果；失败重试复用用户消息/回复槽位。每会话一次仅一轮 pending/running（其余409），lease 防止请求中断永久挂起，序号在锁内分配。
- username 仅 ASCII 字母数字下划线 3..50，规范化小写且禁止 @；email 去两端空白与小写。旧账号不迁移。
- 首版最多14天、request_text最多2000字符、每次最多100行程地点；start_minute范围0..1439，end_minute范围1..1440且严格大于start，过夜住宿拆成逐日段；跨日酒店允许重复。
- 注销需当前密码，在单事务撤销会话、取消非终态任务、删除私有行程/聊天/收藏/行为/偏好，账户保留最小不可登录墓碑与随机不可恢复标识，不保留邮箱和用户名；worker 提交必须再查用户状态。备份保留最长30天且恢复后重放删除记录；正式上线前确定合法保留要求与删除审计。
- trip_add 由服务端地点加入的成功事务产生；客户端只上报 view，服务端接收时间为计量依据，客户端时间仅供参考（最大偏差5分钟），test事件不进入生产推荐。
- B闸门还要求实现完整 Pydantic DTO、示例和导出的 OpenAPI；本文与当前接口文档不能独立视为契约验收已通过。
