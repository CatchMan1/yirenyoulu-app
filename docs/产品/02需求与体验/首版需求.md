# 首版需求 · 鸿蒙与iOS

版本 v0.2，2026-10-14。已确认业务范围；尚待文档评审及实现。两端使用同一账户、同一服务契约和业务规则，分别构建验收。原鸿蒙代码保留，iOS采用React Native方向；不宣称ArkTS可以直接运行于iOS。

## 用户故事与验收

| 编号 | 用户能力 | 必须满足 |
|---|---|---|
| P01 | 注册、登录、资料和账户管理 | 用户名/邮箱+密码；资料编辑、改密、退出和注销；会话过期可恢复登录；邮箱未验证状态真实 |
| P02 | 浏览景点、酒店、餐厅 | 城市、分类、标签、关键词与价格条件；详情和来源更新信息；分页；未知价格/评分/营业时间不填0或编造 |
| P03 | 收藏地点 | 三类地点同一收藏模型；增删幂等；仅本人可读；失效地点显示说明且可取消收藏 |
| P04 | 手动创建和管理行程 | 标题、城市、起止日期、可选预算与偏好；列表、按日查看、编辑、重命名、删除；仅本人可访问 |
| P05 | 编辑行程地点 | 仅从有效目录选择；增删改日期/时段/地点/备注；统一校验；保存失败不改变已确认状态 |
| P06 | Agent生成行程 | 本次目的地、日期、预算、偏好和文本要求优先；任务进度、取消、超时、重试；数据库保存成功才提示成功 |
| P07 | 地图和导航 | 已知坐标可展示并导航；权限拒绝/SDK失败/无外部地图应用时有文本与可用链接降级；无坐标不生成假标记 |
| P08 | AI伴游与历史 | 新建/查看/重命名/删除会话；可绑定本人行程；多轮上下文真实衔接；回复失败能安全重试 |
| P09 | 日常推荐 | 真实行为协同过滤，数据不足时明确偏好/基础推荐兜底；告知推荐依据，不把合成测试称为个性化效果 |

## 产品边界与默认值

首版单城市、1—14天、一人预算，CNY整数分；预算包含计划地点及可得交通费用，未包含项和未知项单列，不等同于报价或可预订价格。这是现有基础与业务规模下的设计默认；若首发海外城市需要其他时区/币种，必须先扩展契约和验收，不能直接上线。

不强制每天“1酒店+2景点+2餐厅”，根据要求与有效候选合理安排；无法满足时给出原因。住宿按每晚一项记录，连续入住可跨日重复；每日最多一项住宿，退房日不超出行程结束日，单日行程不安排住宿。日期变更后地点越界必须明确处理，禁止静默丢失。

首版收藏指地点。本人行程在“我的行程”保存；他人行程收藏、分享、协作和发布不在范围内。旧版行程收藏需求暂缓，见决策记录。

短信、微信登录、订单、支付、预订、会员订阅、打车、天气、UGC评论/评分、自动持续定位和自动重排行程均不进入首版。可展示有授权的第三方评分，但不新增用户评论社区。头像上传需存储与内容处理能力，本期默认使用应用内置头像；资料先支持昵称、签名、明确偏好。

## 数据与隐私体验

测试资料常驻“测试数据”标志，模拟AI显示“模拟服务”。定位只在用户主动使用当前位置时请求；不登录也能浏览公共目录，收藏和私有内容要求登录。不因拒绝定位而禁用全部AI对话。

未知事实使用“暂无资料”；估算展示“估算”及依据。历史行程保留保存时信息，失效/更新提示不伪装为实时事实。未验证的免费模型服务不能展示为已上线能力。

## 完成标准

P01—P09在两端分别具备加载、空、失败、重试与成功流程；关键所有权、事务、幂等与并发测试通过。真实服务未配置的项目独立列为未验收；测试数据闭环与真实服务验收不得混写。具体证据见技术验收矩阵。
