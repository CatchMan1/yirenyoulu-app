# 页面与交互设计

基于旧一期原型的信息架构重新整理，保留首页、行程、我的三个主入口。这里是功能与状态设计，不宣称旧截图已经成为新版视觉定稿；新图标、配色和两端像素级稿在开发前UI评审时确定。

| 页面 | 入口与内容 | 状态和返回行为 |
|---|---|---|
| 注册/登录 | 用户名、邮箱、密码；登录用一个用户名/邮箱输入框 | 字段校验、提交中防连点、统一凭据错误、429等待；登录后回原入口 |
| 首页 | 城市、三类地点入口、开启行程、推荐卡片 | 未选城市提示选择；无行为展示基础/偏好推荐理由；无数据时不摆假热门 |
| 地点列表/搜索 | 城市、类别、标签、关键词、可选最高价格与单位 | 防旧请求覆盖新筛选；分页去重；错误保留筛选并可重试 |
| 地点详情 | 名称、图片或占位、地址、来源时间、价格/营业时间/评分、收藏、地图 | 图片未知许可不用；失效地点警示；匿名收藏先登录；未知坐标仅显示地址 |
| 新建行程 | 城市、日期、预算、偏好、个性化文本；手动创建或Agent规划 | 两个动作含义明确；文本与表单冲突应提示澄清而非猜测；预算单位明确 |
| 生成任务 | queued/running状态、取消、结果或错误 | 显示“生成中”不报创建成功；离页后可从行程页恢复未终态任务；重试沿用幂等键 |
| 行程列表 | 本人行程、搜索标题、新增、重命名/删除；未完成任务入口 | 刷新来自数据库；删除二次确认；无缓存生成ID伪装真实行程 |
| 每日行程 | 日期切换、时间、地点卡片、地图、添加/编辑/删除、伴游入口 | 保存待确认时禁用重复提交；409重新拉取并保留用户输入；删除失败保留卡片 |
| 编辑地点 | 搜索目录、日期/时段（住宿只选入住夜）、备注 | 同城有效地点；无候选不允许自由输入虚构地点；校验错误定位字段 |
| AI会话列表/对话 | 新建会话、可选本人行程、历史消息、重命名/删除 | 单会话一次处理一轮；离页回来恢复状态；失败保留输入，重试不重复消息 |
| 我的 | 资料、偏好、地点收藏、改密、退出、注销 | 改密/注销验证密码；说明删除范围；会话撤销后清除本地私有缓存 |

## 交互不变量

首次加载、刷新、空结果、网络失败、权限拒绝、超时、401、409、429分别处理，不用一个空白页覆盖。无网不宣称写成功；旧数据可只读显示并标注更新时间。首版不做离线编辑队列。

地图标记点击与列表选中共用place_id；切换天数同步过滤。没有路径服务结果时可以显示地点标记，但不能将连线称为实际导航路线。交通时长未知则显示未知，估算必须标记。

定位权限按需询问并可拒绝；拒绝后使用用户选择的城市/行程。调用外部导航前由用户主动点击，避免AI自动打开外部页面。前后台切换停止/恢复轮询，恢复后查询服务端任务状态。

两端共用字段与错误含义，遵循各平台返回、键盘、安全区域、字体缩放和可访问性习惯；不为了同样外观牺牲原生交互。未来UI稿必须逐页对应P01—P09及失败状态。

每日详情将住宿单独显示为“当晚住宿”，不与白天活动时段冲突；连续入住按夜计费，不把跨午夜拆段当成两次住宿。历史失效地点可保留并警告，不妨碍重命名、删除或修改其他地点；更换地点才刷新该项事实。
