# 新旧需求对照

| 原资料内容 | 新版处理 | 原因 |
|---|---|---|
| 奇屿/萤途名称 | 统一一人有路 | 当前项目名称 |
| 手机号验证码登录 | 用户名/邮箱密码；短信暂缓 | 用户已确认 |
| 微信登录接入资料 | 历史参考，无首版入口 | 用户未要求接入 |
| TOPSIS/熵权/主题概率 | 不迁入字段或强制兼容 | 当前推荐与Agent要求 |
| 每天固定酒店/两景点/两餐厅 | 由本次要求和事实候选决定 | 避免凑数和无效安排 |
| 3张地点表、多种ID | places统一UUID，kind区分 | 收藏、行程、工具同一标识 |
| 路线缓存ID与数据库两套详情 | 任务+数据库行程单一真源 | 避免保存失败假成功 |
| 默认评分0、交通距离0 | 缺失null，事实和估算分开 | 真实性 |
| 首版行为埋点暂缓 | 首版最小真实行为链路 | 协同过滤需要真实交互 |
| 用户评论/多维打分 | 首版不做UGC，授权来源评分可展示 | 避免额外社区治理范围 |
| 行程收藏 | 首版仅地点收藏；本人行程正常管理 | 当前统一契约；他人行程隐私 |
| 打车/天气/购票/MCP任意服务 | 暂缓；只用受控只读目录/交通工具 | 首版范围及费用/权限控制 |
| 进入AI立即索取位置 | 用户主动用当前位置时请求 | 拒绝定位仍可伴游 |
| Gitee+develop团队模板 | 新GitHub短功能分支+审查 | 隔离授权与小规模团队 |
| Flask/MySQL/Redis样板方案 | 实际FastAPI+PostgreSQL+Alembic | 核对旧真实代码，避免文档误导 |
| API 12/多个response格式 | 旧项目构建API21；新版统一契约 | 旧规范并不等同于真实构建配置 |
| 仅鸿蒙 | 鸿蒙与React Native iOS分别实现 | 用户最新范围 |
| 补贴、价格与商业KPI数字 | 历史假设，不作当前事实 | 未复核，不作商业承诺 |

旧文档中的通用代码示例仅作参考，不自动复制。特别是仅判断HTTP 200、any/强制类型转换、明文日志、开发端口公开、强推示例不进入新版实施规范。
