编号：ITER-03。状态：**待评审**。目标平台：React Native + TypeScript iOS客户端，复用现有FastAPI后端。视觉方向已确认为**自然青绿＋暖白**；本文确定页面、视觉、业务及验收基线，详细视觉稿和实际客户端分别评审。本期完成不等于地图、真实AI、生产部署或App Store发布完成。

## 1. 目标与用户闭环

让用户在自己的iPhone上完成：选择城市 → 浏览/搜索地点 → 查看详情并收藏 → 创建手动行程 → 按日添加和调整地点 → 重新进入应用后查看后端已保存的安排。

体验重点是地点好找、信息可信、每日安排清楚、编辑结果可靠。无授权照片和价格等事实缺失时，界面仍完整可用。匿名用户可浏览公共目录；收藏、行程和账户资料按登录身份管理。

本期不以全国数据采全为开发前置。先用目标开发库中已获准且足以覆盖验收的少量真实资料联调；独立测试环境可使用明确标记的合成资料。其他电脑补充数据后再执行目标库回归，不将其直接合并到客户端包内。

## 3. 视觉规范：自然青绿

### 3.1 风格与颜色

整体简洁、轻松，保留少量旅行手账的温度。页面以内容和操作为主，首页偏发现，每日行程偏安排；不使用大面积装饰渐变、厚重阴影或无依据的宣传榜单。

浅色主色与暖白背景属于已确认方向；下表其余色值及尺寸为本期设计基线，通过详细稿检查后统一实现为语义主题，不在各页面分别选色。

| 用途 | 浅色 | 深色 | 使用规则 |
|---|---|---|---|
| 主色 | `#246B5A` | `#7BC4A3` | 主按钮、当前标签、选中导航、关键操作 |
| 主色按下 | `#1C5548` | `#9BD4B9` | 按下反馈，不表示另一业务状态 |
| 主色浅底 | `#E8F0EC` | `#20392D` | 选中标签与轻提示，文字使用可读前景色 |
| 页面背景 | `#F7F8F5` | `#111A16` | 暖白/深绿灰背景 |
| 卡片背景 | `#FFFFFF` | `#1B2721` | 内容卡片与表单区域 |
| 主要文字 | `#1F2A25` | `#F1F5F1` | 名称、标题、正文 |
| 次要文字 | `#5E6B63` | `#ACB9AF` | 来源、辅助说明，不能用于淡化重要错误 |
| 分隔/边框 | `#DCE4DE` | `#34483C` | 分区、输入框边界 |
| 沙金点缀 | `#C49A58` | `#D8B67C` | 小面积装饰，不单独承载正文、选中或状态含义 |
| 警告文字 | `#8A520E` | `#E5BD76` | 资料失效、信息不完整等说明 |
| 错误/危险操作 | `#B42318` | `#FFB4AB` | 字段错误、失败、删除和注销确认 |

浅色主按钮使用白字，深色主按钮使用深绿黑字；所有实际文字/背景组合需检查对比，正文目标至少4.5:1。成功、错误、选中和失效同时使用文字或图标，不仅依赖颜色。随系统切换深浅色，深色不通过简单反转图片和颜色实现。

### 3.2 排版、组件与图片

- 使用系统字体；设计参考字号为首页主标题28pt、页面标题22pt、卡片标题18pt、正文16pt、辅助说明14pt、次级来源12pt。支持系统字体缩放，重要信息可折行，不能因大字号消失。
- 采用4pt间距基线，常用8/12/16/24/32pt；页面水平留白20pt。以390pt宽为视觉参考，小屏、大屏、键盘弹出及底部安全区域单独检查，不用固定屏幕高度拼页面。
- 卡片圆角16pt、输入框与按钮12pt、标签使用胶囊形。常规按钮高48pt，图标按钮可点击区域至少44×44pt；大字体下允许增高。卡片优先细边框，阴影轻且统一。
- 主按钮实色，次操作描边或文字；同一区域有清楚的主要操作。危险操作用独立确认，不与创建/保存混为相同主按钮。
- 地点列表采用小图＋信息的纵向列表；详情仅在有可展示图片时使用顶部图片区。无图使用三类统一几何图形占位，不用其他城市或商家的照片冒充该地点。
- 图标使用一致的线性风格。收藏同时提供选中状态与无障碍标签；图片、字体和图标资源的使用范围须适合实际交付。
- 页面切换、选中和保存反馈保持轻量；遵循系统减少动态效果设置，不让装饰动画延迟操作。首次加载骨架与最终内容结构相近，未知事实不是加载骨架。

## 4. 信息架构与页面设计

主导航为**探索／行程／我的**三个入口，分别保留返回栈。探索对应整体产品的首页。详情页通过导航栈打开；表单和筛选使用页面或底部面板，返回及取消行为统一。

| 页面 | 内容与视觉顺序 | 主要动作与约束 |
|---|---|---|
| 探索首页 | 当前城市 → 搜索 → 景点/酒店/餐厅入口 → 创建行程 → 推荐地点及依据 | 首次使用主动选择城市，不请求定位；无城市数据提供更换城市，不放假热门 |
| 城市选择 | 城市搜索、分页结果、当前选择 | 只使用后端城市目录；城市存在不表示三类地点齐全，不标“已覆盖全城” |
| 地点列表/搜索 | 城市和类型 → 关键词 → 筛选标签 → 地点行 → 加载更多 | 支持分类、明确标签、可选价格上限及单位；切换城市/类型重置不适用条件；地点行进入详情，不提供快捷收藏 |
| 地点详情 | 名称/类型 → 合法图片或占位 → 地址/坐标 → 事实资料 → 来源与日期 → 收藏/加入行程 | 未知价格、评分、营业时间用“暂无资料”；本期不显示地图按钮，不把active写成“营业中” |
| 注册/登录 | 产品标识、必要字段、字段错误、提交按钮、模式切换 | 登录一个用户名/邮箱输入框；注册用户名/邮箱/密码；无短信、微信或模拟送信 |
| 收藏 | 类型切换、地点列表、失效摘要 | 可进入有效详情、取消收藏或选择地点加入行程；失效记录可取消，不可新加入 |
| 行程列表 | 标题、新建入口、标题搜索、行程卡片 | 卡片显示城市/起止日期；不显示不存在的封面或预算完成率；删除需确认 |
| 新建/编辑行程 | 标题、城市、日期、预算、偏好、保存 | 仅手动创建；编辑已有行程不提供城市修改；日期修改前提示会影响已有地点 |
| 每日行程 | 行程信息 → 日期切换 → 当日时间线 → 当晚住宿 → 成本/缺失提示 → 添加地点 | 白天地点按时间排列，住宿独立；空的一天提供添加入口；不伪造交通线和路程耗时 |
| 添加/编辑地点 | 选地点 → 日期/时段 → 备注 → 确认 | 从同城有效目录选择；酒店选入住夜，非酒店选起止时间；支持从详情带入地点 |
| 我的/资料/账户设置 | 登录状态、内置头像、昵称/签名、偏好、收藏、账户操作 | 匿名可访问说明和登录入口；显示真实邮箱验证状态；改密/注销要求验证当前密码 |

收藏操作放在地点详情和本人收藏页，探索/推荐/搜索列表本期不放快捷收藏。本人收藏页以服务端列表为已收藏依据；详情按下节的本人收藏状态查询显示。状态读取中禁用切换，失败只提示并重试该状态，不默认当作未收藏；匿名显示“登录后收藏”。收藏成功返回上一页时使相关本人列表和状态重新同步。

“从详情加入行程”先选择本人的同城行程，再选择有效日期和时间；没有可选行程时引导创建手动行程，创建成功后返回该地点的添加表单，不自动添加未确认的地点。改变探索城市不修改已有行程城市。

登录引导保存来源页面和非敏感筛选意图，登录后返回原入口。写操作需要明确确认；不将旧账户未完成请求用新账户身份自动重放。表单有未保存修改时，主动返回提供继续编辑/放弃选择；不承诺跨应用重启恢复未提交草稿。

| I03-10 | 关键状态与交付 | 具备下节状态矩阵、必要自动检查和关键回归；模拟器与至少一台实际iPhone分别记录结果；未验证的外部能力不计入通过 |

账户中的邮箱验证/找回仅如实说明本期未接入；不出现“邮件已发送”或模拟验证成功。账户注销须说明将删除的私有内容及不可撤销性，成功后进入匿名态并清理本地私人缓存；注销失败保留当前账户并说明结果。退出时本地凭据必须清除，远端撤销未确认时不能声称全部会话已撤销，按账户契约处理后续恢复。

### 行程规则

- 复用首版单城市、1—14天、CNY及目的地日历日期规则；金额输入以元显示、提交为整数分，不通过浮点误差改变预算。未知预算与明确0元区分。
- 手动创建先提交空行程；收到已提交的201及行程ID后进入每日详情。新增地点收到完整行程后更新界面及version，不自行拼造已保存ID。
- 住宿按入住夜，时间为空，每夜最多一项；退房日不可额外加入一晚，单日行程不安排住宿。白天地点起止时间成组，冲突和重复按服务端规则定位提示。
- 缩短日期导致地点越界时保留输入和原安排，提示先调整或移除对应地点，不静默删除。不同日期允许按规则复用地点，不用客户端全行程去重误删连续住宿。
- 成本展示使用后端汇总，区分已知事实、估算、未知及未包含项目；不将部分已知费用标成完整旅行总价或可预订报价。
- 行程保存时有版本冲突，读取最新数据并保留用户草稿供比较和重做，不能用新version静默覆盖他处修改。

## 6. 状态与异常交互矩阵

| 条件 | 页面表现与恢复 |
|---|---|
| 首次加载/刷新/加载更多 | 分别有反馈；刷新保留已读内容，下一页失败在列表尾重试；不同时追加重复页 |
| 首次无城市/目录无数据/筛选无结果 | 给出选择城市、更换类型或清空条件入口，不用假地点填空 |
| 无收藏/无行程/当日无地点 | 解释当前为空，并提供对应浏览、创建或添加动作 |
| 无图/坐标/价格/营业时间/评分 | 图片采用占位，事实用“暂无资料”；来源日期未知不填当前时间，无评分不画满星 |
| 断网/超时/5xx/协议解析失败 | 保留筛选和表单，说明未确认结果并提供合规重试；空列表不冒充成功 |
| 登录过期/会话恢复失败 | 仅按当前账户恢复或转登录，返回原入口；旧响应不得清理新账户会话 |
| 权限或资源不可访问 | 不展示其他用户资源；404提示不可访问并返回所属列表，失效收藏用摘要展示 |
| 版本冲突409 | 提醒资料已变化，拉取最新版本并保留本次输入，重新确认后再保存 |
| 输入422/限流429 | 对应字段或业务组合提示；限流按Retry-After等待，不持续自动点击重试 |
| 写入中/结果不确定 | 防重复提交；创建使用相同意图的幂等键恢复结果；无幂等保障的修改先重新读取，不自动盲重试 |
| 地点失效/来源资格变化 | 列表与可选目录遵从后端，历史快照按返回警示或隐藏受限事实，不从旧缓存恢复被撤回资料 |
| 后台/恢复前台/账户切换 | 暂停非必要工作，恢复时重新确认私人数据与会话；敏感草稿和缓存不得跨账户混用 |

## 7. 接口与工程边界

复用`/api/v1`，不因iOS另建一套业务协议。字段、请求校验及所有权以[OpenAPI](../../技术开发/02接口与权限/openapi.json)为准；本节只映射客户端范围。

| 客户端能力 | 现有接口组 |
|---|---|
| 认证与账户 | `/auth/register`、`/auth/login`、`/auth/refresh`、`/auth/logout`、`/me`、`/me/password` |
| 城市/分类/标签 | `GET /cities`、`GET /categories`、`GET /tags` |
| 地点详情与列表 | `GET /places`、`GET /places/{place_id}` |
| 收藏 | `GET /favorites`、`PUT/DELETE /favorites/{place_id}` |
| 手动行程 | `/trips`、`/trips/{trip_id}`、`/trips/{trip_id}/items`及其单项编辑/删除接口 |
| 推荐与真实浏览事件 | `GET /recommendations`、`POST /behavior-events` |

**待补齐的最小接口需求：本人单地点收藏状态。** 当前地点DTO不含本人收藏状态，收藏列表分页也不能证明未加载地点“未收藏”。本期设计新增`GET /favorites/{place_id}`，要求本人身份，成功200按统一包装返回`data: {place_id, is_favorited}`、`meta: null`及`request_id`。仅查询当前用户的收藏关系：合法UUID未收藏时返回false，不区分地点不存在、不可展示或被其他用户收藏；已在本人收藏中的失效地点仍返回true。非法UUID与无效会话遵从422/401规则，不泄露其他用户关系。该接口目前尚未实现，需在3B先同步OpenAPI/DTO、后端及权限回归，再接入详情；本次需求编写不改变现有协议文件。

不以遍历全部收藏分页建立状态，也不因当前页找不到而显示“未收藏”。查询能力未完成时，只能在隔离设计演示中明确模拟，不能将真实客户端收藏能力标为验收通过。

请求层统一解包data/meta/request_id，支持200/201/202/204与标准错误。收藏204无JSON正文，地点新增返回完整Trip；公开城市搜索和地点搜索都保留分页，不把首页有限候选当完整目录。

价格筛选必须选择单一类型及对应计价单位，未知价不满足上限。明确标签使用接口定义的all匹配，偏好标签和硬筛选语义不混淆。匿名浏览不发送要求本人身份的行为事件；开发联调行为由服务端按环境标记为test，不补造真实行为。客户端不显示运营审批/导入入口，也不直接访问数据库或调用模型。

客户端目录为`frontend/ios`；框架、工作流、最低iOS、Xcode和依赖组合在实施前以实际构建锁定，不在需求文档虚构已验证版本。凭据采用平台安全存储，会话与缓存规则遵循现有规范。前台组件不保存数据库配置，日志不记录密码、令牌、聊天和完整位置。

若联调发现接口缺失，先提出最小契约变更及后端回归；不能将后端未实现功能用客户端假数据、任意SQL或成功占位补齐。城市选择和地点文字展示不依赖定位或地图授权。
