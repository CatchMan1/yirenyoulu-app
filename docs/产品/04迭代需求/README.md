# 迭代需求

每一期有独立编号和需求文档，在开发前明确范围、交付物、验收条件及外部依赖。需求变更更新对应文档，由Git保留版本；不把开发会话或操作流水写入需求正文。

## 期次目录

| 期次 | 主题 | 状态 | 交付边界 |
|---|---|---|---|
| [第01期](第01期-后端与鸿蒙迁移.md) | 后端与鸿蒙客户端迁移 | 待验收 | 后端测试数据闭环；鸿蒙源码交付，编译与联调暂缓 |
| [第02期](第02期-全国地点数据采集与导入.md) | 全国地点数据采集与导入 | 待验收 | 来源政策、受控导入、城市推荐及12条开放真实样本；全国扩量另行确认 |

一期编号表示开发迭代，与数据库迁移版本、API版本和产品发布版本分别管理。后续期次在启动前建立文档；未确定的工作不预先承诺完成日期。

## 每期文档结构

1. 编号、名称、状态与目标。
2. 业务范围、非目标及与整体产品的关系。
3. 需求编号、交付内容和可验证的验收标准。
4. 接口、数据、客户端及环境影响。
5. 依赖、待决事项和风险处理。
6. 推进顺序、交付物及完成条件。

状态采用待评审/已确认/开发中/待验收/已验收；只有实际验收通过才能标已验收。存在核心阻塞时保留当前状态并说明依赖，不能以模拟结果替代真实服务结果。每项需求保留固定编号；删改需求同步修改验收，不另留一套失效正文。

共享产品与技术规则直接链接维护，不在每期重复整份接口或开发规范。实施结果写入对应提交、测试产物及发布说明；本目录维护面向产品经理与开发者的需求和交付范围。
