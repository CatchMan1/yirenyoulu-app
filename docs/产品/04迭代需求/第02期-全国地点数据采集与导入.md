# 第02期：全国地点数据采集与导入

编号：ITER-02。状态：待验收。当前为实施需求，面向中国大陆多城市逐步覆盖；数量随数据授权、质量、处理能力和维护资源扩展，不预设仅支持少数城市。本期已确认允许以后端闭环为前置进行少量许可明确的开放数据样本，鸿蒙/iOS验收继续暂缓；交付可自行运行的城市批量采集程序，全国规模验证与商业来源仍分别验收、确认。

依据：[首版需求](../02需求与体验/首版需求.md)、[数据来源与导入设计](../../技术开发/03数据库/数据来源与导入设计.md)、[数据字典](../../技术开发/03数据库/数据字典.md)、[Agent与推荐](../../技术开发/04智能服务/Agent与推荐.md)。

## 1. 本期目标

建立可按城市重复采集、校验、审核、导入及更新的真实地点库，覆盖景点、酒店、餐厅。地点库服务浏览、搜索、筛选、收藏、地图、规划候选和明确偏好推荐；真实行为协同推荐另按有效行为样本验收。

长期以尽可能多城市为目标。城市目录、来源覆盖与可规划城市分别标记：有城市名称不等于有可用地点，有部分地点不等于三类数据完整或能够规划。界面不得把来源记录数显示成全国覆盖率。

## 2. 来源与获取方向

以下为候选渠道。来源类型、已核实能力和仍需确认的许可分开记录；官方网页可访问不自动表示允许批量采集、长期存储、商业展示或复用图片。

| 数据 | 首选调研渠道 | 计划获取内容与方式 | 采用条件 |
|---|---|---|---|
| 城市与行政区划 | 民政部门行政区划资料、地方公共数据平台 | 省市区关系、区划代码、别名、版本；优先公开下载或许可接口 | 核验版本、可复用字段、获取条款；行政边界图形不默认采集 |
| 景点目录 | [文化和旅游部数据服务](https://sjfw.mct.gov.cn/site/dataservice/base)、各地文旅局/公共数据平台 | 景点名称、城市、类别、等级及可用地址；优先数据集/API，再评估允许的页面提取 | 名录不等于完整城市目录，旧名单不等于仍在营业；逐来源确认再用 |
| 门票与开放时间 | 景区/博物馆官方网站、明确开放的地方数据集 | 票种、适用日期、淡旺季、开放时间及核验时间 | 不把一个最低票价当所有人的通用价格；价格过期保留未知 |
| 酒店 | 官方星级名录、酒店/品牌官网授权数据、允许使用的开放地点数据 | 门店身份、地址、品牌/类型、已核验星级及坐标 | 星级与用户评分分开；无日期/房型/入住条件的动态报价不作为固定每晚事实价 |
| 餐厅 | 商家/品牌官网授权门店数据、开放地点数据、许可明确的地方美食名录 | 门店身份、地址、菜系、营业时间、坐标及可证实的人均信息 | 旅游推荐名录不等于完整餐厅库；缺少消费信息时不编造人均价 |
| 跨城市地点补充 | [OpenStreetMap](https://www.openstreetmap.org/copyright?locale=en-GB)，可评估 [Geofabrik 中国分区数据](https://download.geofabrik.de/asia/china.html) | 使用许可数据文件离线筛选三类地点，先测各城市覆盖与字段完整度 | ODbL 的署名、衍生数据库共享义务及与地图服务条款兼容性需落实后再采用 |
| 景点结构化补充 | [Wikidata](https://www.wikidata.org/wiki/Wikidata:Licensing) | 结构化外部标识、地点类别及可核验的地理属性，按字段择优补充 | 结构化数据为 CC0；文本页面和链接指向的图片许可另核，信息真实性仍需验证 |
| 图片 | 自有/商家授权图片、逐文件核验的 [Wikimedia Commons](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia) | 文件、作者、许可版本、署名、原页、展示/处理权限 | 许可不清不展示；下载可用不等于任何用途均可用 |
| 用户行为 | 本 App 用户实际产生的浏览、收藏、取消收藏、加入行程 | 沿现有后端事件与事务链记录，按隐私告知、必要性和注销清理处理 | 不采集外部用户身份、评论历史或伪造行为填充协同阈值 |

可核查实例：北京市公共数据目录列有等级景区门票及星级饭店数据，门票字段包含淡旺季价格，饭店字段包含名称、星级和地址。它证明有候选数据入口，不证明所有城市都有同等数据或已经取得本项目授权。[北京市2025年公共数据开放目录](https://data.beijing.gov.cn/docs/2025.pdf)

景点的营业时间与票种优先核对景区官方；酒店、餐厅的经营状态与报价优先核对商家授权来源。缺失字段允许保留未知，不能从其他平台不明来源的转存数据补齐。

### 高德与商业平台的位置

高德继续作为地图、路线及受授权查询的候选。其当前服务协议第3.4条涉及模型/算法训练与数据集构建，第3.5条涉及存储、缓存及脱离服务使用；不能凭已有 API Key 就认定可建立长期地点库或供推荐计算。若要使用其数据，需明确书面授权范围、费用和存储/计算限制后再决定。[高德服务协议](https://lbs.amap.com/pages/terms/)

携程、美团、点评等可列为后续授权合作候选，不预设存在可免费获取全国门店数据的接口。例如美团门店查询文档要求业务授权；授权商家查询不等于全国数据授权。[美团门店查询](https://developer.meituan.com/docs/api/foodmop-shop-queryShops)

大范围 OSM 数据优先评估下载文件与离线处理，不把公共 Overpass 服务当无限量批量接口；具体实例的使用政策须另核。[Overpass使用说明](https://wiki.openstreetmap.org/wiki/Overpass_API)

## 3. 根据当前模型确定字段

共同必需：稳定内部 place_id、source、source 内稳定 external_id、名称、kind、城市、有效状态、抓取/核验时间及许可记录。跨来源不能以名称作为唯一键。

| 类型 | 共同字段以外的重点字段 | 未知值处理 |
|---|---|---|
| 景点 | 类别/标签、地址、坐标/CRS、票价/票种条件、营业时间 | 价格、时刻、评分、坐标可空，并标明缺失原因 |
| 酒店 | 地址、坐标/CRS、酒店类型、来源明确的星级、条件化每晚报价 | 无可靠入住条件/日期报价时价格未知；不扩展预订/房态 |
| 餐厅 | 地址、坐标/CRS、菜系、营业时间、可核验的人均信息 | 不以外卖起送价或单品价格冒充人均价 |
| 图片 | 独立来源、作者、许可、署名及展示权限 | 无权或无图时采用占位 |

金额为整数分，分别按 entry/night/person 计价。首批采用 CNY，其他币种需另补比较与换算规则。经纬度与 CRS 必须完整成组，原始坐标系如实记录；转换需可验证，不通过改标签伪装转换。正式景区等级和酒店星级不填进用户评分字段。

对票种、报价条件、字段来源/观测时间、许可期限和缺失原因，先设计最小扩展与迁移，再接采集，不强塞到无法表达含义的现有字段里。标签只使用有事实依据的规则映射；“适合独自旅行”“安全”等判断不得当采集事实或由模型无依据填充。

## 4. 导入与更新链路

来源登记与许可核验 → 限速获取 → 隔离区 → 字段/坐标/去重检查 → 抽样审核 → 事务入库 → 业务回归 → 增量更新与失效处理。

需实现：

- 按来源、城市、类别管理批次，持久化游标/检查点、摘要、重试次数、结果统计及失败原因。
- 同源按稳定外部ID幂等更新；跨源按城市、名称、地理距离等产生疑似重复候选，审核后映射同一 place_id。
- 记录字段来源、观察时间、优先级，避免旧价或弱来源覆盖较新事实。原始响应的保留范围和时长服从来源许可。
- 来源许可到期、撤权或不允许展示时，阻止相应字段/地点继续展示或参加计算，并按条款清理；不仅保存备注。
- 地点关闭或来源确认失效时置 inactive，已保存行程快照稳定保留；单次请求没有结果不直接判停业。
- 处理限流、超时、失败重试和断点恢复，固定请求预算与停止阈值。费用、账号或协议变动需确认后才执行。
- dev/test/prod 独立运行；开发数据不得作为生产用户行为。正式来源与 fixture 分开，按环境审核发布。

已实现来源政策、范围许可、批次审核、逐行检查点与字段来源迁移，操作见[来源运营指南](../../技术开发/03数据库/地点数据导入与来源管理.md)。另提供[按城市批量采集程序](../../技术开发/03数据库/批量采集运行指南.md)：操作者配置城市QID后，程序按三类地点分页自动发现候选、核验城市及归属、暂存并按显式`--apply`授权入库，持久化任务、分页游标、候选快照与失败原因。支持同配置重跑、按任务ID恢复和无网络状态查询。程序不自动枚举全国城市、不自动定时运行；全国覆盖与性能仍须实测。跨源按规范化名称发现疑似重复并人工登记别名，距离模糊匹配暂未实现。

## 5. 全国覆盖与推荐规模

- 建立全国可扩展城市目录及别名/区划版本映射，按来源实际覆盖进度记录三类地点数量、字段完整度和新鲜度。
- 每个来源一个受控适配器，采集任务按城市/类别拆分，可失败重跑和持续增加城市，不写死个别城市名单。
- 已按城市分批计算、发布和保留推荐模型；每城市最多2000个有行为地点，行为和收藏分别有10万条保护上限。查询先SQL硬筛选和排序，再限制返回量，避免只读全国前1000条。仍需按真实城市规模验证性能与资源预算，不能直接抬高保护上限。
- 地点库支撑偏好/基础推荐及规划候选。协同推荐需本 App 的真实行为，外部平台评分不是行为矩阵；不足时保留明确兜底。
- 全站/城市级数据量不等于推荐效果。质量与效果分别验收，不承诺采集完成即可证明个性化有效。

下列数量为建议验证规模，不是全国覆盖上限，也不是已批准调用额度。

| 阶段 | 工作 | 通过条件 |

| 2B 少量真实样本 | 当前验证北京、上海、杭州共13条；不为凑90条或字段完整度编造事实 | 逐条核验，浏览、搜索、收藏、地图/坐标、规划候选、推荐硬过滤可验证；真实服务未通项明确记录 |
| 2C 城市批次试运行 | 建议5–10城，每城约100–300条，最终以来源和预算为准 | 重复导入、断点/重试、增量、失效/撤权、历史快照、规模过滤测试通过 |

## 7. 验收重点与交付物

验收至少包含：三类真实资料的来源与许可、必填字段和未知值、坐标/CRS、同源重复/跨源冲突、失败重试/断点、增量更新/失效、许可撤回、图片控制、行程快照稳定、所有权隔离，以及真实数据下的接口与推荐过滤回归。

交付来源与字段矩阵、版本化迁移、导入/更新入口与运行说明、隔离审核及导入报告、可复现测试、城市覆盖与质量报告，以及按实际结果编写的第02期验收。
