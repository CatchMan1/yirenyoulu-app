# 第01期：后端与鸿蒙客户端迁移

编号：ITER-01。状态：待评审。目标平台：Python FastAPI后端、ArkTS/ArkUI鸿蒙。交付类型：基于隔离测试数据的开发版本。

## 1. 目标

以现有后端和鸿蒙项目为业务来源，复用有效代码与页面，按当前产品需求、接口契约和工程规范完成迁移改造。交付一个可重复启动、可构建、可验证的后端与鸿蒙业务闭环，为后续iOS接入同一服务提供基础。

“整体迁移”指对原后端与鸿蒙业务模块完整核对、明确处置并实现本期范围，不是复制全部文件或保持旧接口兼容。数据模型、身份权限、事务、持久任务和前端请求必须符合新版契约；旧实现不满足时改写相应部分。代码复制完成或表结构存在不能作为验收结果。

## 2. 依据与边界

本期遵循[首版需求](../02需求与体验/首版需求.md)、[API契约](../../技术开发/02接口与权限/API契约.md)、[业务不变量](../../技术开发/02接口与权限/数据传输结构.md)、[联调规范](../../技术开发/02接口与权限/联调与兼容规范.md)和[代码规范](../../技术开发/09代码规范/通用工程规范.md)。字段约束以[OpenAPI](../../技术开发/02接口与权限/openapi.json)为准，迁移不能另建一套隐式接口。

原后端与原鸿蒙前端只读保留；迁入独立新仓库及独立环境，不导入旧Git历史、数据库、用户账号、配置或签名材料，不向Gitee推送。鸿蒙来源为原前端仓库的现有ArkTS工程；新版代码目标为frontend/harmony，不以当前工作分支名称推断源码已迁入。

本期覆盖整体首版的后端能力与鸿蒙实现。iOS React Native客户端在后续期次接入；因此本期完成不代表双端验收或正式数据采集条件全部满足。

### 不在本期

- 创建或实现React Native iOS工程。
- 订单、支付、预订、会员、社交、UGC评论、短信和微信登录。
- 迁入TOPSIS、熵权、概率特征、Excel数据兜底或进程内缓存行程。
- 迁移真实账号、个人数据、旧数据集，或正式地点采集/批量导入。
- 开通付费服务、接受商业协议、生产上线及商店提交。
- 为迁移额外引入微服务、消息总线或无业务需求的中间件。

## 3. 迁移处置范围

文件路径为原工程内相对路径，用于定位复用对象，不要求逐文件照搬。

| 来源模块/页面 | 新版归属 | 处置要求 |
|---|---|---|
| 后端app/main.py、core/config.py、core/db.py | 应用入口、settings、db | 复用有效配置思路；显式环境、生命周期、独立Session和迁移管理 |
| api/routes/auth.py、api/deps.py、core/security.py | auth、账户 | 改为用户名/邮箱密码、UUID主体、可撤销会话与统一权限 |
| attractions.py、hotels.py、restaurants.py、search.py | catalog | 统一places标识与筛选契约，保留有效查询规则 |
| favorites.py | favorites | 统一place_id，去重及本人归属，服务端行为随事务产生 |
| trips.py、trip_management.py | trips、planning | 统一数据库行程和持久任务，去除缓存详情双源及假成功 |
| ai.py、ai_sessions.py、ai_service.py | chat、模型适配 | 本人会话、有界多轮上下文、原位重试和可识别失败 |
| recommendation_service.py、recommendations.py | recommendations | 复用通用过滤；重建真实行为协同与冷启动兜底，不迁入旧排序模型 |
| amap_service.py、navigation_service.py | 地图/导航适配 | 审查后复用有效参数构建；限制供应商、坐标系与凭据位置 |
| models/、schemas/、db_utils.py | 新ORM/DTO/Alembic | 以现有新库为基线补迁移；不覆盖新版17表或复制启动补列逻辑 |
| Main/Home/Attraction/Hotel/Restaurant/Search及详情页 | 首页、目录与详情 | 保留可用布局/组件，改为新DTO、空值、分页及状态 |

| Route/TripPlanning/Loading/TripDetail/PlaceSelection页 | 行程与规划 | 持久化确认、任务恢复、按日编辑、住宿与版本冲突 |

| ApiService.ets、DataModels.ets、Logger及公共组件 | 请求/DTO/日志/组件 | 拆清职责，201/202/204、运行时解码、安全存储和资源释放 |
| VerificationCode/ChangePhone/Footprint等超范围入口 | 不进入本期界面 | 移除首版导航与依赖；对应原代码继续保存在原工程 |

迁入代码需检查依赖、资源许可及敏感配置。自有UI资源可复用，第三方图片/地点资料权利不明时改用占位；签名、旧环境、构建物和依赖目录不迁入。

## 4. 需求清单

### I01-01 工程与运行基础

- 后端保留模块化结构，提供明确API、规划worker及推荐计算入口；进程使用同版本领域代码。
- 鸿蒙工程位于frontend/harmony，保留有效ArkUI页面；SDK/DevEco/Hvigor依赖使用经验证组合，不直接套用文档版本。
- 开发/测试/生产配置分离；旧项目不读写，新项目不隐式读取旧环境。安全配置样例无秘密。
- 提供初始化、启动、停止、测试与构建说明；从干净检出可按说明恢复开发环境。

验收：新库可初始化，API live/ready行为符合契约；worker可独立启动，鸿蒙可实际编译；缺配置明确失败且不泄露秘密。不能以静态检查代替鸿蒙构建。

### I01-02 DTO、路由与数据库改造

- 实现当前OpenAPI全部44个操作的路由/DTO，保留operationId、字段、状态码及鉴权含义；不提供旧版路由兼容壳。
- 邮件发送在提供方未配置时走明确503不可用，开发可注入隔离模拟；真实邮件不属于本期核心通过项。
- 补齐住宿空分钟、手动创建幂等、任务结果删除、刷新凭据重放、邮箱一次凭据、注销审计和必要费用/交通来源结构。
- 已应用迁移不改写，用新Alembic版本升级；现有fixture保持独立且幂等。

验收：实现导出的OpenAPI与设计语义一致；PostgreSQL迁移、约束、无漂移及回滚测试通过；全接口无密码/hash/token内部字段越界输出。schema形状检查之外另验事务与跨字段规则。

### I01-03 注册登录、资料及账户管理

- 鸿蒙实现用户名/邮箱密码注册登录、本人资料/偏好编辑、改密、退出及注销。
- 短期访问token、旋转刷新、撤销/重放、账户状态校验按契约实现；用户密码不进入日志。
- 安全存储适配和session epoch处理启动恢复、迟到401、账户切换和退出竞争。
- 邮箱验证/找回页面提供已启用流程或明确不可用状态；模拟不能显示为真实送信。

验收：正常流程可用，错密码不触发refresh；失效/撤销凭据不能继续访问；其他用户数据不可读写；改密/注销撤销会话并清理私有缓存。注销取消任务并删除私有内容，删除审计可供隔离恢复验证。

### I01-04 地点浏览、筛选、搜索与收藏

- 景点/酒店/餐厅使用同一地点ID，支持城市、分类、硬标签、关键词、价格单位及分页。
- 详情展示来源与测试标记；价格/评分/时间/坐标缺失保持未知，不生成假事实。
- 收藏增删幂等，失效摘要可查看/取消，不允许加入新行程。
- 修复筛选竞态、加载更多重复和账户缓存混用，保留失败重试和空结果状态。

验收：鸿蒙与后端对相同筛选返回一致结果；未知价不满足价格上限；已收藏重复提交不新增行为；两账户收藏互不影响。

### I01-05 手动行程与每日地点编辑

- 创建、列表/标题搜索、按日详情、重命名/日期/预算编辑及删除；增删改目录地点。
- 统一城市、日期、时段、重复、住宿和预算验证；保留快照并提示目录失效。
- version并发控制与创建幂等；完整提交后才提示成功。
- 删除生成行程保留任务结果墓碑，不能用旧键复活行程。

验收：保存失败全回滚且界面不报成功；冲突409保留输入；同日住宿唯一、连续两夜费用正确、退房不越界；失效历史地点不阻止重命名/删除其他项；跨用户及子资源错配404。

### I01-06 Agent规划与持久任务

- 鸿蒙规划表单提交本次城市、日期、预算、偏好与文本，创建任务202并恢复状态。
- worker只通过受控工具查询有效目录，无任意SQL；程序重建事实并在保存前统一验证。
- 队列/运行/成功/失败/超时/取消、deadline、租约generation与重复请求均落库。
- 开发测试用确定性FakePlanner验证全链路并明确mock；生产拒绝模拟。

验收：任务成功必有完整已提交行程，取消与保存竞争结果唯一；过期worker不能写；同键只保存一次；无候选/非法ID/未知费用/超时均按契约反馈。真实模型未接入时记录为未验证，不影响模拟链路验收，也不满足真实服务发布验收。

### I01-07 推荐行为与冷启动

- 客户端view去重，收藏/取消/加入行程行为由服务端成功事务产生。
- 实现协同计算入口、候选过滤、版本与接口；数据不足时明确偏好/基础兜底。
- fixture/test行为隔离，不能进入真实统计；本次硬要求优先历史排序。

验收：可手算合成样本证明去重、相似度与过滤；正常测试库无真实行为时实际走兜底。重复事件先查摘要再判首次时间窗口；不宣称个性化效果已验证。

### I01-08 AI伴游和历史会话

- 会话增查改删、绑定本人行程、消息游标、按序显示与有界多轮上下文。
- message_id、内容摘要、单轮租约和固定消息槽位；仅最后失败轮可原位重试。
- 隔离模拟provider验证回复/失败/超时；缺真实免费模型不返回冒充真实的回复。

验收：两账户会话隔离；最近20条成功完整消息与当前行程正确进入上下文；失败重试不重复追加，旧失败轮409；会话删除与在途回复竞争不复活数据。

### I01-09 地图、导航与平台权限

- 迁入地图/导航适配边界与页面能力；高德为已有来源方向，接入仍需核验鸿蒙SDK和权限范围。
- 坐标带CRS，已知坐标测试标记，未知坐标保留地址；拒绝定位不阻止目录、手动选城市和伴游。
- SDK/导航App不可用、CRS不支持等降级；链接不暴露后端密钥。

验收：测试桩覆盖正常与失败；编译验证适配层；有合法凭据和设备后另做真实SDK/导航验证。没有真实凭据只能标“降级/模拟通过、真实地图未验证”，不能将地图功能整体标完成。

### I01-10 自动检查与交付

- 后端静态/类型/关键测试、PostgreSQL迁移与事务并发；鸿蒙ArkTS编译、关键UI状态及接口样例检查。
- 保留日志脱敏、依赖锁定、源码/暂存/可达历史上传扫描。
- 更新启动、构建、配置和当前实现状态，开发者按文档可重复验证交付物。

验收：相关检查可重复运行且有实际结果；只提交本期范围，仓库无密钥、签名、数据库、个人数据或未授权素材。

## 5. 推进与交付顺序

一期内按可验证的工作包推进，每包以通过的测试和提交为边界；它们仍属于同一期，不扩展成未经定义的新期次。

1. 模块/资源允许清单与依赖审查，建立新版后端/鸿蒙工程构建基线。
2. DTO/OpenAPI与新迁移；认证、目录、收藏。
3. 手动行程、共享验证器、幂等与快照。
4. 持久规划任务、推荐行为与AI会话；先注入测试provider。
5. 鸿蒙逐页接入并完成加载/空/错误/重试及安全存储。
6. PostgreSQL故障/并发与鸿蒙联调回归，整理实际交付范围。

建议实施分支feat/01-backend-harmony-migration，从已同步主分支建立。前后端在同仓分别构建，后端数据库与环境不随分支自动隔离。

## 6. 测试数据及外部依赖

使用少量名称含【测试】的虚拟城市/地点、独立测试账户和无真实个人信息的消息。不从旧库或旧Excel导入事实；用于地图/预算边界的合成坐标、价格仅在明确测试夹具/事务中，不伪装为真实地点。生产拒绝fixture/mock。

| 依赖 | 本期处理 | 验收影响 |
|---|---|---|
| PostgreSQL与后端环境 | 独立开发/测试实例，迁移及集成验证 | 必须实际通过，不能只用SQLite |
| DevEco/SDK/可运行鸿蒙环境 | 核对并建立构建与联调工具链 | 无法构建或运行时，本期不能通过核心验收 |
| 鸿蒙签名与设备 | 本地或受控配置，不迁旧材料 | 记录模拟器/设备范围；真实平台能力单独验收 |
| 地图SDK/Key/商业授权 | 模拟与降级先行，现有合法配置可受控接入 | 真实地图未验证时作为明确缺项 |
| 免费模型/模型许可 | FakePlanner/FakeChat验证；真实服务待配置 | 模拟闭环可验，不宣称真实AI已可上线 |
| 邮件服务与回链 | 一次凭据流程模拟或统一不可用 | 真实邮箱验证/恢复为发布阻塞，不假送信 |
| 恢复审计与备份 | 独立测试库做备份/恢复及删除重放演练 | 演练未完成不标账户数据保护验收通过 |

未提供账号不触发购买或协议接受；运行环境与密钥通过私密配置注入，不写入需求文档。

## 7. 交付物与验收

| 交付物 | 必需结果 |
|---|---|
| backend/ | 可启动API、持久worker、协同计算入口、供应商适配、DTO/权限/事务 |
| frontend/harmony/ | 可构建及运行的页面、请求/DTO、安全会话、任务恢复与失败态 |
